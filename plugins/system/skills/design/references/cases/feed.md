# 케이스: 무한 스크롤 피드

SNS 홈·타임라인·추천 콘텐츠처럼 **피드 자체가 제품인 화면**. 무한스크롤을 **채택할지 말지**는 이 파일이 아니라 `cases/list-and-detail.md`의 L3에서 정한다 — 여기는 채택 이후의 설계다.

`core-questions.md` C1~C8을 먼저 진행하고 아래를 얹는다.

---

## D1. 페이지네이션 방식 — 확정형

**커서 방식만 쓴다.** `page=3` 같은 오프셋은 체류 중 새 글이 앞에 삽입되면 이미 본 항목이 다시 내려오고(중복), DB도 건너뛸 행을 전부 스캔한다. 피드에서 오프셋을 정당화하는 조건은 없다.

- **커서는 불투명 토큰으로 다룬다** — 파싱·조작·저장 형식을 가정하지 않고 받은 그대로 되돌려준다. 백엔드가 값 커서든 스냅샷 커서든 계약이 같아야 교체가 가능하다.
- 백엔드에 확인할 것 2개: "커서가 행 존재에 의존하는가(삭제된 항목 안전한가)" / 랭킹 정렬이면 "스냅샷 커서인가, 만료는 어떻게 되는가".
- **id 기반 중복 제거를 항상 안전망으로** 넣는다. 커서가 완벽해도 실시간 삽입·재요청 경계에서 중복은 생긴다.

근거: `topics/cursor-pagination.md`

## D2. 화면 밖 항목을 어떻게 다룰까 — 추천형 (3단)

- 한 세션에 쌓이는 항목이 **수십**: 아무것도 하지 않는다. 최적화 비용이 더 크다.
- **수백 또는 이미지·영상 중심**: CSS `content-visibility: auto` + `contain-intrinsic-size`. 라이브러리 없이 화면 밖 렌더 비용을 브라우저가 건너뛴다.
- **수천·초장기 세션**: 동적 측정 가상화(추정 높이 → 실측 → 보정). 오버스캔은 항목 개수가 아니라 **뷰포트 높이 단위(±1~2)**로 잡는다.
- 어느 단이든 이미지에 `aspect-ratio`를 미리 지정한다 — 높이 추정 정확도와 레이아웃 밀림을 함께 잡는다.
- 가상화를 채택하면 **포기하는 것**(브라우저 Ctrl+F 찾기, 화면 밖 항목의 접근성 트리)을 사용자에게 고지하고 기록한다.

근거: `topics/render-window.md`

## D3. 상세 갔다 돌아오기 — 추천형

➡️ **1순위는 피드를 언마운트하지 않는 것.** 라우터가 허용하면(앱 스택 내비게이션, Next.js 인터셉팅 라우트 등) 상세를 스택·모달로 열고 URL만 바꾼다. 피드 DOM·스크롤·측정치가 그대로 살아 복원 문제 자체가 사라진다.
➡️ 전체 언마운트가 불가피하면: 무한쿼리 캐시(로드한 전체 페이지) + sessionStorage(스크롤 오프셋·로드 페이지 수)로 **근사 복원**을 수용한다. 순서는 데이터 → 측정 → 스크롤.

근거: `topics/return-and-merge.md`

## D4. 체류 중 생긴 새 글 — 추천형

➡️ 위→아래로 읽는 타임라인이면 **자동 삽입 금지, "새 게시물 N개" 버튼**(수동 병합 + 클릭 시 맨 위로). 읽던 화면이 밀리는 것이 자동 삽입의 대가다.
➡️ 맨 아래가 최신인 채팅형 소비만 자동 append를 허용한다.
➡️ 당겨서 새로고침은 부분 갱신이 아니라 **전체 갱신(커서 리셋)**으로 취급한다.

## D5. 다음 페이지를 언제 부를까 — 확정형

센티널 요소 + IntersectionObserver. 바닥에 닿아서가 아니라 **남은 1~2 뷰포트 전에 미리** 부른다. 로딩 중 재진입 중복 요청을 가드하고(`isFetchingNextPage` 등), 실패 시 자동 무한 재시도 대신 **수동 재시도 버튼**을 둔다. 끝에 도달하면 명시적으로 끝을 표시한다.

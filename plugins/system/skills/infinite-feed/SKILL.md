# infinite-feed — 무한 피드 설계 판정

무한 스크롤 피드의 **설계 결정 5축**을 판정한다. 무한스크롤을 쓸지 말지는 이 스킬 소관이 아니다 — 그 판정은 `list-filter-detail`(축③ S8)이 담당하고, 이 스킬은 **채택이 끝난 뒤**의 설계를 다룬다. 각 결정의 "왜"와 "무엇을 포기하는지"는 references/가 근거다.

## 사용 방법 — 이중 모드

1. **판독 먼저.** 아래 신호표의 각 신호를 요청 문장·기획서·API 명세·기존 코드베이스에서 읽는다. 읽을 수 있는 신호는 **묻지 않는다** — 파악한 것은 "이렇게 이해했다"로 확인만 한다.
2. **판독 불가한 신호만 문답.** 사용자와 대화 중이면 AskUserQuestion 등으로 묻는다(선택지에 트레이드오프를 붙여서). 자율 실행 중이라 물을 수 없으면 각 신호의 **기본값**을 채택하고, 산출물에 "이 신호는 확인 못 해 기본값 사용"을 명시한다.
3. **판정표 적용.** 신호 조합 → 5축 결정. 자기 취향이 아니라 이 문서의 판정을 따른다 — 판정과 다르게 가려면 근거를 사용자에게 확인받는다.
4. **설계 틀 출력.** 아래 출력 형식으로 결정·근거·포기한 것을 제시한 뒤 구현에 들어간다.

## 신호표 — 질문지이자 판독 기준

| # | 신호 | 판독 위치 | 기본값(판독·문답 불가 시) |
|---|------|----------|--------------------------|
| F1 | 정렬이 시간순인가 랭킹(추천·인기)인가 | API 명세·기획서의 "추천/인기" 언급 | 시간순 |
| F2 | 한 세션에 쌓이는 아이템 규모 (수십/수백/수천) | 평균 체류 시간·도메인 성격 | 수백 |
| F3 | 미디어 중심 카드인가 (이미지·영상) | 디자인 시안·기획서 | 예 |
| F4 | 카드→상세→복귀가 핵심 동선인가 | 상세 화면(댓글 등) 존재 여부 | 예 |
| F5 | 체류 중 새 콘텐츠가 생기는가 | 도메인 — SNS·뉴스 예, 아카이브·검색결과 아니오 | 아니오 |
| F6 | 소비 방향 — 위→아래 타임라인인가, 맨 아래 고정(채팅)인가 | 화면 구조 | 타임라인 |
| F7 | 내비게이션이 피드를 살려둘 수 있는가 (스택·모달 상세) | 라우터 구조 — 앱 스택 내비, Next.js 인터셉팅 라우트 등 | — (반드시 판독 가능) |

## 판정표 — 신호 → 5축 결정

**축 ① 페이지네이션** → 상세: `references/cursor-pagination.md`

- **항상 커서 방식.** 오프셋(`page=3`)은 체류 중 새 글이 앞에 삽입되면 이미 본 항목이 다시 내려오고(중복), DB도 건너뛸 행을 전부 스캔한다. 피드에서 오프셋을 정당화하는 신호는 없다.
- FE 계약: **커서는 불투명 토큰** — 파싱·조작·저장 형식 가정 금지, 받은 그대로 되돌려준다. 백엔드가 값 커서든 스냅샷 커서든 계약은 동일해야 교체 가능하다.
- API 협의 시 백엔드 확인 질문 2개: "커서가 행 존재에 의존하는가(삭제 안전)?" / F1 랭킹이면 "스냅샷 커서인가, 만료 정책은?"
- 페이지 병합 시 **id 기반 중복 제거를 안전망으로** 항상 넣는다 — 커서가 완벽해도 실시간 삽입·재요청 경계에서 중복은 생긴다.

**축 ② 렌더 윈도우** → 상세: `references/render-window.md` (3단 판정)

- F2 수십 규모: 아무것도 안 한다 — 최적화 비용이 더 크다.
- F2 수백 또는 F3 미디어 중심: **CSS `content-visibility: auto` + `contain-intrinsic-size`** — 라이브러리 없이 화면 밖 렌더 비용을 브라우저가 스킵.
- F2 수천·초장기 세션: **동적 측정 가상화**(추정 높이 → 실측 → 보정). 오버스캔은 아이템 개수가 아니라 **뷰포트 높이 단위(±1~2)**로.
- 어느 단이든 이미지에 `aspect-ratio` 사전 지정 — 추정 정확도와 CLS를 함께 잡는다.

**축 ③ 복귀 복원** → 상세: `references/return-and-merge.md`

- F4 예(기본): **1순위 = 피드를 언마운트하지 않는다.** F7이 가능하면 상세를 스택·모달(+URL 동반)로 열어 피드 DOM·스크롤·측정치를 그대로 살린다 — 복원 문제 자체가 소멸한다.
- F7 불가(풀 언마운트): TanStack Query 무한쿼리 캐시(로드한 전체 페이지) + sessionStorage(스크롤 오프셋·로드 페이지 수) 조합의 **근사 복원**을 수용한다. 순서는 데이터 → 측정 → 스크롤.

**축 ④ 새 글 병합** — F5 예 + F6 타임라인: **자동 삽입 금지, "새 게시물 N개" 버튼**(수동 병합 + 클릭 시 맨 위로). 읽던 화면이 밀리는 것이 자동 삽입의 비용이다. F6 채팅형(맨 아래 고정 소비)만 자동 append 허용. 당겨서 새로고침은 전체 갱신(커서 리셋)으로 취급한다.

**축 ⑤ 페칭 트리거** — 센티널 요소 + IntersectionObserver. 바닥에 닿아서가 아니라 **잔여 1~2뷰포트 전에 프리페치**. 로딩 중 재진입 중복 요청 가드(TQ `isFetchingNextPage` 등). 실패 시 자동 무한 재시도 금지 — 수동 재시도 버튼. 끝(`hasNextPage` false)에는 명시적 끝 표시.

## 출력 형식 — 설계 틀

판정을 마치면 구현 전에 이 형식으로 제시한다:

```
## 설계 판정: {기능명}
| 축 | 결정 | 근거(신호) | 포기하는 것 |
|----|------|-----------|------------|
| 페이지네이션 | 커서 + 불투명 토큰 | F1 시간순 | 임의 페이지 점프·전체 개수 |
| ... | | | |
확인 못 한 신호: {있으면 — 기본값 채택 사실 명시}
```

사용자가 대화 중이면 이 표를 승인받고 구현, 자율 실행이면 표를 산출물에 남기고 진행한다.

## 주의사항

- 이 스킬은 **설계 판정까지**다 — 구현 패턴(IntersectionObserver 코드·스켈레톤·당겨서 새로고침 제스처)은 fe-ui 스킬이 담당한다.
- 가상화를 채택하면 포기하는 것(브라우저 찾기 Ctrl+F, 화면 밖 항목의 접근성 트리)을 출력에 명시하고 사용자에게 고지한다.
- SEO가 필요한 콘텐츠라면 무한 피드는 크롤러에 뒷페이지가 보이지 않는다 — 채택 자체를 `list-filter-detail` 축③으로 재검토하라.

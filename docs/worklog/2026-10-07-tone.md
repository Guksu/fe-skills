## 1. 개요

사용자 요청은 "벤치마크에서 suta로 만든 화면이 아직 AI 슬롭 같다. 폰트 크기·색·레이아웃을 생각해서 더 개선하자. 우리가 조사한 레퍼런스를 참조하는 게 우선이다"였다.

- 1차 벤치마크에서 suta 화면은 결함 지표가 거의 0이었지만, 판정은 "깔끔하지만 밋밋하다"였다.
- 레퍼런스(앱 화면 기록·디자인 피드백 사례·웹사이트)를 글자·색·면 기준으로 다시 보고, 그 근거로 스킬을 고쳤다.
- 바뀐 스킬로 suta 쪽을 다시 돌려(2차) 같은 일반 산출물과 비교했다.

## 2. 작업내용

- **진단**
  - 1차 suta 화면 16개를 일반 화면과 나란히 보고, 판정 이유 64개를 다시 읽었다.
  - 레퍼런스와 같은 측정 스크립트로 재 보니 차이는 세 군데였다.
    - 본문이 보조 크기다: 가장 많은 글자 14px(레퍼런스 16px). 작은 글자의 양은 레퍼런스 모바일 범위 안이었다.
    - 면이 하나다: 16개 중 10개가 흰 바탕 하나에 선만 썼다.
    - 강조색이 기본값이다: 16개 중 9개가 프레임워크 기본 파랑이었고, 주 버튼에만 쓰였다.
- **레퍼런스 재분석** → `docs/research/2026-10-07-tone.md`
  - 앱 화면 1,104장의 기록과 관찰 메모(스크래치패드에 남아 있던 것)를 다시 집계했다.
    - 카드의 71%가 테두리·그림자 없음, 구역 사이 8px 띠(25곳), 회색 채움 상자(28곳).
    - 채운 버튼 색은 서비스마다 다르다. 강조색은 선택 상태·탭·링크에 이어 쓴다.
    - 소셜 로그인은 서비스 고유 색, 장바구니의 전체 선택 줄, 설정의 두 방식(띠 / 회색 바탕 위 흰 묶음).
  - 디자인 피드백 사례(색 45·타이포 47·대시보드 14·랜딩 38)를 다시 읽었다.
  - 웹사이트 19곳(앞 조사와 같은 목록, robots 허용)의 글자색·면·자간·행간을 새로 쟀다.
    - 본문 행간 1.41~1.5, 큰 글자 1.2, 자간 0, 무채색 면 1~2종, 넓은 면에 테두리·그림자 없음(중앙값 100%).
- **토큰**(`layout-tokens.css`·`layoutTokens.ts` — layout-audit 복사본도 같이)
  - 색 역할 11개를 더했다: 글자 3단계·선·흰 면·옅은 바탕·강조색(기본값 거의 검정)·글자 위 강조색·상태 색 셋.
  - 글자 색은 흰 면과 옅은 바탕 모두에서 4.5:1 이상이다. `contrastRatio`와 테스트 6개로 잰다(TDD — 먼저 실패를 확인했다).
  - 구역 사이 48 → 32(넓은 화면 48), 구역 사이 띠 `--band` 8, 본문 행간 1.6 → 1.5.
  - 글자 크기 값은 바꾸지 않았다. 값이 아니라 쓰임(본문 자리에 보조 크기)이 문제였다.

- **벤치마크 하네스** — `measure.mjs`에 톤 지표 5개(가장 많은 글자 크기·15px 미만 글자 비율·강조색 글자 비율·무채색 면 종류·주 버튼 색상각)를 더했다. `report.mjs`는 톤 표(레퍼런스 값과 함께)와 결과 파일 이름 옵션(`--name`)을 받는다.
- **벤치마크 2차** — 바뀐 스킬로 suta 쪽 16회를 다시 돌렸다(일반 쪽은 1차 산출물 재사용).
  - 판정 중 두 가지를 바로잡았다.
    - 레퍼런스 톤 측정이 들여쓰기 공백만 있는 요소도 글자로 셌다. 공백을 뺀 글자 수와 조상까지 본 보임 판정으로 고쳐 다시 쟀다. 그 결과 "15px 미만 글자가 많다"는 진단은 틀린 것으로 나와 문서에서 뺐다(잘 만든 모바일 사이트도 59%). "본문 자리가 14px"만 남겼다.
    - 2차 3개 화면이 `position: sticky` 하단 바를 써서, 전체 캡처에서 바가 페이지 중간에 찍혔다. 캡처 때 아래쪽 sticky 바를 제자리로 돌리도록 `measure.mjs`를 고치고 판정을 다시 했다.
  - 근거 없는 화면 9개가 모두 짙은 청록을 골라 새 기본값이 됐다. 사용자 결정으로 "근거가 없으면 거의 검정" 규칙을 더하고, 근거 없는 4종(로그인·대시보드·랜딩·장바구니)만 3차로 다시 돌려 교체했다.
  - 결과(일반 → suta 2차)
    - 가장 많은 글자 13 → 16px(1차 suta 14).
    - 파랑·남색·보라 주 버튼 10 → 0/16(1차 suta 8).
    - 회색 면 1 → 1종(1차 suta 0).
    - 결함 지표는 1차 수준, 접근성 위반 87 → 13건(1차 suta 4건).
  - 판정: 기본 판정 모델 11 : 21(1차 7 : 25), 다른 판정 모델 19 : 13(1차 14 : 18).
  - 문서·README 두 벌·비교 이미지를 2차 기준으로 바꿨다. 1차 결과는 `evals/benchmark/results-r1.json`에 톤 지표와 함께 남겼다.
- **버전** 0.5.1 → 0.6.0.

## 3. 주의사항

- **2차 벤치마크의 일반 쪽은 1차 산출물을 그대로 썼다.** 같은 요청문·같은 기본 모델·같은 설정이라 다시 돌리지 않았다. suta 쪽 16개 중 4종 8개는 규칙 하나를 더한 3차 결과다.
- **강조색 기본값은 거의 검정이다.** 스킬은 서비스에 맞게 바꾸라고 하지만, 토큰 파일을 그대로 쓰면 무채색 화면이 된다.
- **레퍼런스 웹사이트는 브랜드·포트폴리오 사이트가 많다.** 면·강조색은 앱 기록을 먼저 보고 웹 측정을 보조로 썼다. 자간은 레퍼런스 근거가 없어 규칙을 만들지 않았다.
- **원자료는 저장소에 넣지 않았다.** 레퍼런스 측정 원본과 벤치마크 산출물은 세션 임시 폴더에 있다.
- **남은 과제**(2차 판정 이유)
  - 사진 파일을 못 쓰는 요청에서 회색 칸 + 선 아이콘 자리표시가 "와이어프레임 같다"는 평을 들었다. 자리표시 기준을 다시 정할 필요가 있다.
  - 장바구니 1개 화면의 빈 상태 동시 노출, 긴 이메일 줄바꿈, 약한 로그인 링크.
  - 접근성 위반이 1차보다 늘었다(대부분 `aria-label`이 보이는 글자와 다름). 스킬에 "보이는 글자를 aria-label에 포함한다"를 넣을지 검토한다.
- 설치되는 패턴 코드의 warn 22건(척도 밖 간격 등)은 이번 범위가 아니라 그대로다.

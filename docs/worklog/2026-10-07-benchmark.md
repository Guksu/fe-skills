# 퍼블리싱 벤치마크 — 일반 Claude Code와 suta

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-10-07 |
| 작성 | 에이전트 (Claude Code) |
| 관련 경로 | `scripts/benchmark/`, `evals/benchmark/`, `docs/benchmark.md`, `docs/benchmark.en.md`, `README.md`, `README.en.md` |

## 1. 개요

사용자 요청은 "벤치마크 지표를 측정하고 리드미 상단에 넣자. 일반 클로드 모델에게 퍼블리싱을 지시하는 것과 우리 스킬을 사용한 퍼블리싱 지시를 비교한다"였다.

- 같은 요청문을 두 Claude Code에 그대로 준다. 하나는 아무것도 설치하지 않았고, 다른 하나는 suta 플러그인만 설치했다.
- 만든 화면을 브라우저로 열어, suta 검사기와 따로 만든 렌더 지표와 axe-core로 잰다.

## 2. 작업내용

- **하네스** `scripts/benchmark/`
  - `run.mjs` — 같은 요청문을 두 조건의 `claude -p`에 준다.
    - 실행마다 빈 폴더, 새 세션이다. 부모 세션에서 물려받는 환경 변수(세션 ID·추가 CLAUDE.md 폴더·생각 수준 등)는 지운다.
    - suta 조건은 실행마다 플러그인 복사본을 `--plugin-dir`로 싣고, `--add-dir`로 그 폴더를 읽게 연다.
    - 권한은 두 조건이 같다: 작업 폴더 안 쓰기 자동 승인, 셸 전체 허용.
    - stream-json 기록에서 시간·토큰·도구 사용·스킬 읽음·읽은 패턴·훅 반응·권한 거절 수를 뽑는다. 끊기면 같은 명령으로 이어서 돈다.
  - `measure.mjs` — 산출물을 Chromium으로 열어 렌더 지표, axe-core(WCAG A·AA), suta 검사를 잰다.
    - 스크린샷은 고정 요소를 스크롤 처음·끝 자리로 옮겨 찍는다.
  - `judge.mjs` — 블라인드 판정. 순서를 바꿔 두 번 판정하고, 판정 모델을 바꿀 수 있다.
  - `report.mjs` — 조건별로 모아 `evals/benchmark/results.json`과 표를 만든다.
- **요청문** `evals/benchmark/prompts.json` — 화면 유형 8개(상세·폼·설정·대시보드·랜딩·장바구니·목록·인터랙션).
- **실행** — 요청 8 × 조건 2 × 2회 = 32회(동시 4개), 판정 32회 × 판정 모델 2개.
- **결과**(조건마다 화면 16개)
  - 결함 지표: 접근성 위반(axe) 87 → 4건, 상자 안 상자 41 → 0, 강한 효과 47 → 0, 24px 미만 터치 영역 27 → 0.
  - 12px 미만 글자가 있는 화면은 4 → 0, 320px 가로 넘침은 2 → 0, 글자 크기 종류는 화면당 8.1 → 4.1이다.
  - 차이가 없던 것: 두 조건 모두 `transition: all`을 쓰지 않았다. 동작 줄이기 대응은 일반 쪽도 15개 중 14개가 했다.
  - 블라인드 판정: 일반 쪽 우세 — 기본 판정 모델 25:7, 다른 판정 모델 18:14.
    - suta가 진 이유는 "깔끔하지만 밋밋하다"(묶음 카드 없음, 소셜 버튼 단색, 회색 링크, 데스크톱의 덩그러니 놓인 열)가 많았다.
    - suta는 일반 쪽에 마감 결함(깨진 그래프·끊긴 제목)이 있을 때 이겼다.
  - 비용: 시간 중앙값 61 → 96초, 입력 토큰 4.3배, 출력 토큰 1.5배.
  - 스킬은 16회 모두 읽혔다. 훅은 warn을 6번 돌려보냈고, error로 막은 적은 없다.
- **문서**
  - `docs/benchmark.md`·`docs/benchmark.en.md` — 방법·결과·판정 이유·해석·한계·다시 돌리기.
  - README 두 벌 맨 위에 요약 표와 판정 결과 한 문단을 넣었다.
  - 비교 이미지 `docs/assets/benchmark-compare.jpg` — 요청 순서대로 처음 세 개(1회차). 고르지 않고 규칙으로 정했다.
  - AGENTS.md(구조·명령), 상세 안내 두 벌(구조·관련 문서), 설계 문서 12라운드, CLAUDE.md 변경 이력에도 반영했다.
- **진행 중 바로잡은 것**
  1. 파일럿에서 모델이 긴 작업 경로를 잘못 옮겨 적었다(`…/fe-skills/4930…` → `…/fe-skills-4930…`). 그래서 작업 폴더 밖 쓰기로 거절됐다. 짧은 경로(`/home/user/suta-bench`)로 옮겼다.
  2. 첫 본 실행은 셸을 읽기 명령만 허용했다. 그래서 suta 쪽이 패턴 문서와 검사기를 읽지 못했다(권한 거절). 셸 전체 허용·`--add-dir`·권한 거절 기록을 더하고 32회를 모두 다시 돌렸다.
  3. 지표를 보정했다.
     - 아바타·토글처럼 원·알약 모양이거나 이름이 컨트롤인 요소는 상자로 세지 않는다.
     - `grid-template-rows` 기법은 레이아웃 애니메이션과 따로 표시한다.
     - 측정 브라우저를 한국어로 맞췄다. 브라우저 언어를 따르는 페이지가 영어로 찍히던 문제다.
  4. 전체 화면 캡처가 고정 바를 페이지 중간에 찍었다. 그래서 판정자가 "바가 내용을 가린다"고 오판했다(실제로 끝까지 내리면 가리지 않는다). 고정 요소를 스크롤 끝 자리로 옮겨 다시 찍고 판정을 다시 했다. 처음 판정은 일반 23 : suta 9였고, 다시 한 판정은 25 : 7이다.
  5. 파일럿의 판정 기준에는 suta 규칙과 겹치는 목록이 있었다. 중립 문장("숙련된 프로덕트 디자이너가 그대로 내보낼 쪽")으로 바꿨다.

## 3. 주의사항

- **다시 돌리면 사용량이 든다.** claude CLI 32회 + 판정 64회다. 동시 4개로 실행 약 25분, 판정 약 10분이 걸렸다.
- **원자료는 저장소에 넣지 않았다.** 산출물 HTML·스크린샷·대화 기록은 저장소 밖 작업 폴더에서 만들었다. 저장소에는 요약(`results.json`, 판정 이유 원문 포함)과 비교 이미지 한 장만 남겼다.
- **실행·판정 모델 이름은 결과 파일에 적지 않는다.** `--model`을 주지 않으면 Claude Code 기본 모델로 돈다.
- **해석의 개선 후보는 suta 규칙을 바꾸는 일이라 이번에 하지 않았다.** 사용자가 정한다. 후보는 다섯 가지다.
  - 설정 화면의 묶음 목록(inset grouped)
  - 소셜 로그인 버튼의 브랜드 색
  - 링크처럼 보이는 링크
  - 넓은 화면에 놓는 모바일 열의 바탕·틀
  - 덜어낼 것은 장식이지 기능이 아니라는 점
- 한 모델·한 설정·조건마다 화면 16개라는 한계는 문서의 "한계" 절에 적었다.

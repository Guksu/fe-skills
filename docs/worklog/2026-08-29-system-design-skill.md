## 1. 개요

세 번째 시스템 케이스(다단계 폼)를 문답으로 설계하던 중, 사용자가 축마다 "도메인·기획에 따라 다르니 물어보자"로 답하면서 기존 **판정표 방식의 한계**가 드러났다. 좁은 케이스(무한 피드)는 업계 합의로 판정이 가능하지만, 넓은 케이스(퍼널 폼 전반)는 판정표가 "그때그때 다름"으로 채워진다. 사용자가 스킬의 노선 자체를 재검토(“차라리 무엇을 물어야 할지 정하는 스킬로?”, grill-me 참조)했고, 문답 4라운드로 **2계층 하이브리드**를 확정했다: 진행 규칙(어떻게 물을지)은 SKILL.md, 질문 트리(무엇을 물을지)는 references. fe-skills는 이제 UI / 설계 두 갈래이며, 설계는 스킬 1개로 수렴한다.

## 2. 작업내용

- **신설 `plugins/system/skills/design/SKILL.md`** — 문답 진행 규칙. ① 사실 조사(프레임워크·라우터·API는 코드베이스에서 읽고 묻지 않음) → ② 프론티어 단위 라운드 문답(질문마다 추천안 필수, 선택지에 대가 명시, 신입 기준 문장) → ③ 결정 기록 파일 생성. **질문 강도 3종**(확정형·추천형·필수 확인형)으로 판정과 문답을 한 틀에 담았다 — 좁은 케이스는 확정형이 많고 넓은 케이스는 추천형이 많아진다.
- **신설 `references/core-questions.md`** — 케이스 파일이 없어도 동작하는 범용 8질문(요구사항·데이터 성격·실행 환경·상태 위치·페칭·복원 요구·실패 처리·포기할 것). 사용자 결정: 미지의 케이스도 거절하지 않고 뼈대로 진행.
- **신설 `references/cases/funnel-form.md`** — 이번 문답의 산출물. 도메인 4갈래(거래·계정·수집·내부도구) → 보관 위치 분기, 단계별 URL + 가드 2종(선행 미완료 되돌리기·완료 후 replace)은 확정형, 이어서하기 3항목(복귀 지점·보관 기간·저장 제외 목록)은 전부 문답, 검사 분할은 단계별 스키마 + 최종 합성, 제출 안전은 갈래별 강도.
- **이관 `references/cases/{list-and-detail,feed}.md`** — 기존 `list-filter-detail`·`infinite-feed` SKILL.md의 결론을 케이스 질문 형식으로 옮김(내용 폐기 아님). 기존 references 6종은 이력을 보존해 `references/topics/`로 이동.
- **신설 `references/topics/submit-safety.md`** — 멱등키·응답 유실 복구 근거 문서(퍼널 폼 F5).
- **삭제** — `plugins/system/skills/list-filter-detail/`, `plugins/system/skills/infinite-feed/` (사용자 결정: 스킬 형태 제거, 내용은 케이스로 흡수).
- **갱신** — `plugins/system/.claude-plugin/plugin.json` description.
- **README 전면 재작성(신입 기준 문장)** — 사용자 요청("20살 신입도 이해할 수 있게"). 도입부를 "이게 뭔가요"로 바꿔 문제 상황부터 설명하고, 용어 3개(스킬·플러그인·마켓플레이스)를 접이식 블록으로 추가. UI 카탈로그 29종 설명을 업계 용어(FLIP·ARIA 콤보박스·`grid-template-rows 0fr↔1fr`·scroll-snap) 대신 **동작 묘사**로 교체하고 섹션명도 평이하게(등장과 전환→나타나고 사라지기, 제스처→손가락 제스처(모바일), 컨트롤→입력 요소). fe-system 섹션은 "왜 설계를 먼저 정하나"의 구체 예(뒤로가기 사고)와 3단계 동작·질문 강도 3종 표로 재구성. 배지 fe-system 2→1, 저장소 구조·기여 절차 문장도 평이하게. `story-progress` 행에 남아 있던 이모지 1개 제거(이전 세션 정규식이 U+23EF를 못 잡음).

## 3. 주의사항

- **게이트 결과**: 빌드 ✓ · 린트 ✓ · 테스트 202/202 ✓ · 스킬 구조 검증 ✓. 데모 사이트는 UI 스킬만 노출하므로 영향 없음.
- **결정 기록의 저장 위치는 실행 중인 프로젝트**의 `docs/design/`이다(fe-skills 레포가 아니다). 스킬이 다른 저장소에서 실행되는 것을 전제로 쓰였으니 경로를 절대경로로 바꾸지 말 것.
- 기존 두 케이스 파일은 **아직 새 틀에서 실사용 검증되지 않았다**. 사용자 결정(Q13-C)에 따라 `funnel-form`으로 실전 사용 후 케이스 파일 형식을 다듬는다.
- 트리거 경계: 설계 문답은 `design`, 모션·컴포넌트 구현은 fe-ui 스킬. `design`의 description이 "화면 기능 구현 요청 시 코드 전에" 발동하도록 쓰여 있어 UI 스킬과 동시에 걸릴 수 있다 — 순서는 설계 → 구현이므로 충돌이 아니라 선후 관계다.
- 이 재구성으로 **판정표 형식은 저장소에서 사라졌다.** 되돌리려면 이 커밋 하나를 되돌리면 되고, 삭제된 두 SKILL.md는 이 커밋 이전 히스토리에 남아 있다.

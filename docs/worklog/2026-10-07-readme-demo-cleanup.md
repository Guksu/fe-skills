- **데모 점검 방법**
  - `node skills/suta/scripts/audit.mjs demo/src`(훅과 같은 검사기)를 돌렸다.
  - Playwright로 데모 55개와 홈을 1280·390·320px에서 열어, 가로 넘침·콘솔 오류·스크린샷을 확인했다.

- **셸(모든 페이지에 걸리는 틀)**
  - 넘침의 원인: 셸 격자의 `1fr` 열이 내용의 최소 폭(사용 예시 코드의 긴 줄)보다 좁아지지 못했다.
    - `minmax(0, 1fr)`과 `.content { min-width: 0 }`으로 고쳤다.
  - 좁은 화면에서는 패턴 목록 55개를 "패턴 목록 55" 버튼 뒤로 접었다.
    - 예전에는 목록이 데모 본문을 다섯 화면 아래로 밀었다. 지금 390px에서 제목이 199px 위치에 나온다.
    - 패턴을 고르면 목록이 닫힌다(`aria-expanded`·`aria-controls`).
    - 메뉴 행과 버튼은 누르는 영역 44px를 지킨다.
  - 값을 토큰으로 바꿨다(`main.tsx`가 layout·motion 토큰 CSS를 셸보다 먼저 불러온다).
    - 글자 크기는 9종에서 5종으로 줄였다. 메뉴 묶음 제목은 11.5px에서 12px로 올렸다.
    - 화면 제목은 32px에서 24px(`--text-title`)로 바꿨다.
  - 색 전환은 100ms ease-out으로 바꾸고, 동작 줄이기 블록을 넣었다.
    - 카드에 마우스를 올리면 떠오르던 효과는 뺐다.
  - 데모 공통 조절 막대(`.controls`)의 상자를 걷었다.
    - 이제 아래 선 하나로 무대와 나눈다. 무대가 이미 상자라, 둘 다 감싸면 상자가 겹쳐 보였다.
    - 조절 막대 안 라디오 묶음(fieldset)도 테두리 없이 제목과 간격으로 묶었다.
    - 라디오가 단추 위·문구 아래로 갈라지던 문제도 고쳤다. 원인은 CSS 순서였다(셸 규칙이 데모 규칙을 덮었다).
  - 데모 공통 `.playground`를 enter-exit 데모 CSS에서 셸로 옮겼다. 54개 데모가 쓰는데 한 데모 파일에 있었다.
- **데모별**
  - 동작 줄이기 누락 3곳을 고쳤다: card-expand, form-shake-error, tab-indicator.
  - 척도 밖 간격이 있는 선언 108개를 4px 척도 토큰으로 맞췄다(스크립트로 바꾸고 줄마다 확인).

    - 목록 행을 상자 대신 선으로 나눴다(14곳): 순서 바꾸기, 수량, 범위 슬라이더, 피드, 유리 GNB, 테마 카드 메뉴, 체크박스 묶음, 드롭다운·스와이프 목록, 검사 결과, 파일 거절 사유, 스크롤 영역 둘.

## 3. 주의사항

- **패턴 코드의 경고 22건은 그대로 두었다.** 대부분 척도 밖 간격이다(`skills/suta/patterns/*/assets/*.css`).
  - 사용자에게 설치되는 코드라 패턴마다 화면을 보고 고쳐야 한다. 별도 작업으로 제안했다.
- **CSS 순서**
  - 데모 CSS는 `App` → 각 데모 순서로 먼저 실리고, 셸(`styles.css`)이 마지막에 실린다.
  - 그래서 셸의 `.controls label` 같은 규칙과 구체성이 같은 데모 규칙은 진다. 데모 쪽에서 이기려면 선택자를 더 구체적으로 쓴다.
- **예외 주석의 기준**
  - 무대(데모 바탕) 위의 폰 틀·주인공 카드는 예외로 둔다.
  - 무대 안 화면의 목록 행은 예외가 아니다. 상자 대신 선으로 나눈다.

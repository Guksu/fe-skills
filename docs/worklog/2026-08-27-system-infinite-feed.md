# fe-system 두 번째 스킬: infinite-feed (화이트보드 세션)

## 1. 개요

fe-system 두 번째 케이스 스킬. 사용자와의 화이트보드 문답(3라운드)으로 "무한 피드" 케이스의 설계 결정 5축을 확정하고 스킬로 굳혔다. **이번 세션부터 진행 방식 교정: 면접관 모드(일방 질문·채점)가 아니라 동료 모드 — 서로 의견·반론을 주고받아 함께 결론 도달.** 브랜치 `feat/system-infinite-feed`(main 분기), 커밋 안 함.

## 2. 작업내용

- **화이트보드 결정 (사용자와 문답·반론 교환으로 확정)**:
  - 축① 페이지네이션: 사용자 원안(커서 — 오프셋의 중복 수신·DB 비용 지적) 유지 + 보완 — 삭제 안전은 "행 포인터"가 아닌 "정렬 키 값 커서"로(±1 보정 불요), 랭킹 피드는 스냅샷 커서, FE 계약은 불투명 토큰(파싱 금지) + 백엔드 확인 질문 3종 + id 중복 제거 안전망.
  - 축② 렌더 윈도우: 사용자 원안(가상 스크롤 — 데이터는 메모리, DOM은 뷰포트 주변) 유지 + 3단 판정으로 확장 — 소규모 무대응 / 수백·미디어 중심 content-visibility / 수천·초장기 동적 측정 가상화. 가변 높이는 추정→실측→보정(위 스크롤 점프 부작용·aspect-ratio 완화), 오버스캔은 개수 아닌 뷰포트 단위(사용자 "레이아웃에 따라 다름" 일반화).
  - 축③ 복귀 복원: 1순위 피드 언마운트 회피(스택·모달 상세+URL), 차선 TQ 무한쿼리 캐시+sessionStorage 근사 복원(순서: 데이터→측정→스크롤). 합의.
  - 축④ 새 글 병합: 타임라인은 자동 삽입 금지+"새 게시물 N개" 수동 병합, 채팅형만 자동 append. 합의.
  - 축⑤ 페칭 트리거: 센티널+잔여 1~2뷰포트 프리페치, 중복 요청 가드, 실패 시 수동 재시도.
- **산출물**: SKILL.md(이중 모드 — 신호표 F1~F7·판정표 5축·출력 형식) + references 3종(cursor-pagination / render-window / return-and-merge, 각 문서에 "왜"와 "포기하는 것" 명시).
- 경계: 무한스크롤 채택 여부는 list-filter-detail(S8) 소관 — SKILL.md 서두·description에 명시. 구현 패턴(옵저버 코드·스켈레톤·제스처)은 fe-ui 몫.
- 게이트: 빌드·린트·테스트·구조 검증 + 트리거 검증(should: "피드 만들어줘"·"돌아오면 스크롤 맨 위로"·"같은 글 두 번" / should-NOT: "스크롤 리빌 애니메이션"(fe-ui)·"상품 목록 필터"(list-filter-detail)).

## 3. 주의사항

- 신호 기본값(F1~F7)은 SNS·콘텐츠 피드 가정 — 커머스 무한 목록 등 다른 도메인이 쌓이면 재검토.
- 화이트보드 진행 방식은 이후 케이스에서도 동료 모드로(사용자 교정 2026-08-27, 메모리 기록됨).
- 다음 케이스 후보: 다단계 폼(장바구니→주문) — 이전 세션부터의 잔여 후보.

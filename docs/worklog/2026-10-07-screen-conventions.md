## 1. 개요

사용자 요청은 "별점이 높은 디자인을 분석해 종합하고, 레이아웃 스킬 또는 훅에 결합하자"였다.

- 처음 받은 사이트는 robots.txt가 검색엔진 외 자동 접근을 모두 막아서 제외했다.
- 사용자가 디자인 레퍼런스 사이트를 다시 제시했고, 범위를 정했다: 앱 화면 분석이 중심이고, 웹사이트 측정으로 보강한다.
- 출처(사이트·서비스 이름)와 화면 이미지는 저장소에 남기지 않는다. 지난 연구와 같은 원칙이다.

## 2. 작업내용

- **수집**(원자료는 세션 임시 폴더에만 두고, 끝난 뒤 지웠다)
  - 앱: 국내 서비스 31곳의 화면 목록 전체(서비스당 132~1,609장, 모두 12,944장)를 사람이 둘러보는 속도로 읽었다.
    - 처음에는 서비스마다 앞쪽 36장을 받았다. 그런데 온보딩·가입 화면에 치우쳐 있었다.
    - 그래서 목록 전체에서 고르게 44곳을 짚어 36장씩 뽑았다. 모두 1,116장이다.
    - 단계 이름만 적힌 구분 카드는 픽셀 규칙(상태 표시줄 없음, 가운데 띠에만 글자)으로 걸러 냈다.
  - 웹: 좋아요순 목록 23곳 중 robots.txt가 허용한 19곳만 열었다. 봇 확인 화면이 뜬 1곳은 풀지 않고 뺐다.
    - 데스크톱(1440)·모바일(390) 폭에서 계산된 스타일을 쟀다.
    - 공개 CSS도 받아 우리 검사기를 돌렸다.
- **분석**
  - 화면 한 장을 고정 형식(JSON) 한 줄로 기록했다. 항목은 유형, 블록 순서, 주 행동 위치·높이, 묶는 수단, 카드 중첩, 여백, 정렬, 원칙 준수 등이다.
  - 서비스 하나를 Sonnet 에이전트 하나가 맡았다.
  - 집계 기준: 서비스마다 비율을 낸 뒤 평균한다. 60% 이상은 관례, 30~60%는 흔한 선택이다.
- **반영 — 스킬**
  - `layout-principles/references/screen-conventions.md`(새 파일): 화면 유형 11종의 뼈대·값·하지 말 것·관련 패턴, 넓은 화면 값.
  - `layout-principles/PATTERN.md`
    - "화면 유형별 관례" 요약 표와 넓은 화면 값을 더했다.
    - P11 코드 기준과 사용 방법 1번에 뼈대 참조를 넣었다. 파일 표와 description도 고쳤다.
  - `SKILL.md`
    - 절차 2번에 화면 유형 뼈대 참조를 넣었다.
    - 금지선을 2행 더했다: 같은 틀로 모든 화면 짜기, 행동 버튼 여러 개를 내용 중간에 채워 두기.
    - 레이아웃 값에 "화면 뼈대"·"넓은 화면" 행을, 체크리스트에 1항목을 더했다.
    - 8번 훅 설명을 "바꾼 줄의 error만"으로 고쳤다.
  - 토큰은 바꾸지 않았다. 측정값이 모두 지금 토큰의 범위 안이었다.
- **반영 — 훅과 검사**
  - 잘 만든 사이트의 CSS에서도 예전 훅은 아무 줄 하나를 고쳐도 편집의 59%를 막았다.
  - `hookCore.ts`: 훅이 이번 편집이 바꾼 줄만 판정한다. 막는 비율은 0.9%로 줄었다.
    - Claude Code는 `tool_response.structuredPatch`, Codex는 apply_patch 구간을 읽는다. 새 파일은 전체를 본다.
    - 원래 있던 error로는 멈추지 않는다. 다른 알림이 나갈 때만 한 줄로 알린다.
  - 요약 지적(척도 밖 간격·종류 수·효과 남발·동작 줄이기 누락)에 관여한 줄 전체(`lines`)를 붙였다.
    - 그래서 요약 지적도 바꾼 줄과 겹칠 때만 알린다.
    - `auditCore.ts`의 `Finding`에 선택 필드로 더했다(motion-audit 원본과 layout-audit 복사본이 같다).
  - `auditLayout.ts`의 tiny-text를 보정했다.
    - 아이콘 글꼴 선택자는 뺀다.
    - rem은 `html`·`:root` 글자 크기로 환산한다(62.5%면 1rem = 10px).
  - 새 규칙 후보 4개는 기각했다(이유는 연구 문서 6절): 안전 영역, 사진 크기 고정, 본문 14px 미만, 버튼 44px 미만.
- **데모**: layout-principles에 ⑥ "메뉴 상세"를 더했다.
  - 고치기 전: 채운 버튼 셋이 내용 중간에 있다.
  - 고친 뒤: 사진 → 이름·가격 → 옵션 → 하단 고정 구매 바(찜 아이콘 + 담기 버튼 하나, 안전 영역 여백).

## 3. 주의사항

- **근거의 한계**
  - 수치는 캡처 픽셀을 390pt 폭으로 환산한 눈대중이라 ±5% 안팎이다.
  - 유형 판정은 에이전트 한 명이 한 서비스를 맡아서 했다. 같은 화면을 두 번 기록해 맞춰 보지는 않았다.
  - 국내 앱 중심이다. 장바구니·결제 화면은 근거가 적다.
- **분석 도중 사용량 한도**: 에이전트를 13개까지 동시에 돌리다 한도에 걸렸다. 재설정 뒤 동시 5개로 낮춰, 끊긴 서비스를 이어서 마쳤다. 기록 형식은 기존 줄을 건너뛰고 이어 쓰게 되어 있다.
- **훅**: diff를 알 수 없는 입력(옛 클라이언트 등)에서는 `new_string` 위치로 찾는다. 그것도 못 찾으면 예전처럼 파일 전체를 본다.
- **데모**: 데모 사이트 셸이 390·320px 폭에서 가로로 넘친다. 이번 변경 전부터 모든 데모 페이지에 있던 문제다.

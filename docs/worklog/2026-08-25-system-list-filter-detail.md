## 1. 개요

fe-system의 첫 케이스 스킬. 사용자와의 화이트보드 면접식 문답(4라운드)으로 "목록+필터+상세" 케이스의 설계 결정 5축을 확정하고 스킬로 굳혔다. 브랜치 `feat/system-list-filter-detail`, 커밋 안 함.

## 2. 작업내용

- **화이트보드 결정 (전부 사용자와 문답으로 확정)**:
  - 축① 상태 위치: URL 쿼리 단일 진실 + 연속 입력만 로컬 에코(디바운스). 기본 replace, 신호 시 push. URL 금지 4종. 사용자 원안(내부 상태+URL 미러)은 뒤로가기 시 화면≠주소 반론으로 URL 파생 읽기로 수정 합의.
  - 축② 데이터 페칭: 사용자의 5분기 트리(CSR/Next.js × 캐시·SEO·국내외) 유지 + 보완 — "왕복 시간"은 대리 신호(SEO 크롤러·LCP·소스 리전)로 판독, "최신값 필수→fetch+상태"는 반론 수용으로 TQ+staleTime 0/폴링으로 교정, 경쟁 상태(필터 연타) 경고 명시.
  - 축③ 기본 페이지네이션, 무한스크롤은 신호(탐색형 소비·모바일) 판정 + 비용 명시.
  - 축④ 기본 라우트, 모달은 신호 + URL 동반(인터셉팅 라우트).
  - 축⑤ 필터·페이지는 URL로 공짜, 스크롤 복원은 캐시 전략의 결과물(TQ 히트 시 자동 / 무한스크롤은 sessionStorage 추가).
- **산출물**: SKILL.md(이중 모드 — 신호표 9종·판독 위치·기본값·판정표·출력 형식) + references 3종(state-location / data-fetching / list-navigation, 각 문서에 "왜"와 "포기하는 것" 명시).
- 게이트: 구조 검증 통과(시스템 분기 — 데모 불요), 트리거 검증(should: "필터 있는 리스트"·"뒤로가기 필터 증발 진단" / should-NOT: UI 효과 요청), README fe-system 목록 갱신.

## 3. 주의사항

- 이 스킬은 설계 판정까지 — 구현 패턴은 fe-ui 몫(SKILL.md에 경계 명시).
- 다음 케이스 후보: 다단계 폼(주문·가입), 무한 피드. 같은 화이트보드 방식으로.

# 실사용 점검 3 — 증권 플랫폼 웹사이트

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-10-09 |
| 계기 | 사용자 요청 — "증권 플랫폼의 웹 사이트를 만들어서 벤치마크 해보자". 범위는 측정 → 개선 → 재측정, 화면 7개 + GNB, 데스크톱 중심에 모바일 확인, 일반 2번·suta 2번(개선 뒤 suta 2번 더) |
| 반영 | `layout-principles`(등락 색 토큰, tone.md 등락 색 예외, screen-conventions.md "증권·투자" 절, 아이콘 채움의 안쪽 선), `layout-audit`(`hue-count`가 등락 색 변수를 따로 센다), `SKILL.md`(절차·금지선·값·체크리스트), 평가, 버전 0.10.0 |

지금까지의 비교는 모두 모바일이었다(이커머스 웹뷰, 단일 화면 벤치마크). 이번에는 데스크톱 중심의 여러 화면 웹사이트로 같은 비교를 했다.

## 1. 방법

이커머스 점검(`2026-10-08-commerce-webview.md`)과 같은 방식이다.

- **프로젝트**: `npm create vite`(React + TypeScript) 직후의 빈 프로젝트.
- **요청문**: 사용자 문장에 네 줄을 붙였다.

  ```text
  증권 플랫폼 웹사이트를 구현해줘.
  홈(시장 개요) / 종목 상세(차트·호가·주문) / 내 자산 / 관심 종목 / 검색 / 거래 내역 / 설정 / GNB가 있어야 해.

  - 이 프로젝트(Vite + React + TypeScript)에 만든다. 화면 사이 이동이 실제로 되게 해 줘.
  - 데스크톱 웹이 기준이고, 모바일 폭에서도 깨지지 않게 해 줘.
  - API는 아직 없으니 종목·시세는 지어낸 목 데이터로 채운다. 실제 회사 이름은 쓰지 않는다.
  - 끝나면 npm run build가 통과해야 한다.
  ```

- **실행**: `claude -p`(CLI 기본 모델)다. 편집은 자동 승인하고 Bash를 허용했다. 조건 사이에 다른 것은 플러그인(`--plugin-dir`) 하나뿐이다.
- **측정**: 빌드한 앱을 `vite preview`로 띄워 화면 7개를 쟀다.
  - 캡처: 1440×900(데스크톱), 390(모바일, 기기 배율 2, 터치), 320(가로 넘침).
  - 검사: axe-core(WCAG A·AA, 1440과 390), suta 통합 검사, 퍼블리싱 벤치마크의 렌더 지표(상자 안 상자·강한 효과·작은 터치 영역·12px 미만 글자·글자 크기 종류).
  - 증권 지표: 등락 글자(`+1.2%`·`▲300` 같은 짧은 글자)의 색과 부호, 3자리 이상 숫자의 `tabular-nums`(같은 폭 숫자) 비율, UI 색 계열.
  - 조작: 종목 상세에서 수량을 넣고 매수 버튼을 눌러 확인 창과 체결까지.
- **블라인드 판정**: 화면마다 일반과 suta 2차를 짝지어(1↔1, 2↔2) 이름 없이 보여 주고 고르게 했다. 퍼블리싱 벤치마크와 같은 중립 문장("숙련된 프로덕트 디자이너가 그대로 내보낼 쪽")이다. 데스크톱 첫 화면과 모바일 화면(2400px까지)을 함께 줬다. 짝마다 순서를 바꿔 두 번, 판정 모델 둘(기본 모델과 다른 모델)로 판정했다.

### 진행 중 바로잡은 것

- **1차 suta 쪽 2번에 플러그인이 실리지 않았다.** 실행 스크립트가 플러그인 경로를 상대 경로로 넘겼다. 자식 claude는 작업 폴더에서 출발하므로 그 경로에 플러그인이 없었다. 초기화 기록의 플러그인 목록에 suta가 없는 것으로 알았다.
  - 그 2번은 일반 조건과 같으므로 일반 쪽 3·4번째 표본으로 썼다.
  - 경로를 절대 경로로 고치고, 초기화 기록에서 실린 플러그인을 남기게 한 뒤 suta 쪽 2번을 다시 돌렸다.

## 3. 레퍼런스

### 웹 — 증권·시세 사이트 10곳

국내 4곳·해외 6곳의 공개 페이지(홈·종목 상세·검색·순위)를 1440과 390에서 쟀다. robots.txt가 허용한 곳만 열었고 로그인하지 않았다. 페이지 사이 4~5초 쉬었다. 모든 봇을 막거나 AI 에이전트를 막은 곳, 연결이 끊긴 곳은 뺐다. 문서에는 사이트 이름을 남기지 않는다.

### 앱 — 디자인 레퍼런스 사이트

이전 조사와 같은 레퍼런스 사이트를 다시 훑었다. 서비스 92곳 중 화면이 공개된 곳은 31곳이고, 독립 증권 앱은 없었다. 증권 화면이 있는 곳은 종합 금융 앱 하나다. 그 앱의 주식 탭 화면 55장(2022년)을 기록했다. 한 서비스의 일관된 사례라 업계 관례보다 약한 근거로 쓴다.

- 상승 빨강·하락 파랑(31장 모두), 부호 29/31, `▲▼` 0/31. 색은 변화량에만.
- 표기는 `+275원 (5.8%)`: 금액에 부호, 비율은 괄호.
- 차트 선 색은 고른 기간의 등락을 따른다.
- 구매하기는 강조색 채움, 판매하기는 옅은 면이다(빨강·파랑으로 나누지 않는다). 하단에 반반으로 고정한다.
- 내 자산: 합계가 가장 큰 글자(28~32), 그 아래 손익을 색으로, 원금·총 수익·일간 수익 요약.
- 거래 내역: 날짜로 묶고, "전체 ▾" 같은 글자 필터가 시트를 연다.
- 관심 종목: 그룹으로 관리하고, 행은 등락률이 위·가격이 아래다.
- 카드 테두리·그림자 없이 회색 띠와 간격으로 나눈다(48/55). 채운 버튼은 화면당 0~1개(53/55).

## 4. 반영 — suta 0.10

- **등락 색 토큰** `layout-tokens.css`
  - `--color-rise: #d0262d`, `--color-fall: #1b64da`(국내 관례). 해외 관례면 값을 바꾼다.
  - 흰 면·옅은 바탕에서 4.5:1 이상이고, 흰 글자를 얹어도 4.5:1 이상이다. 오류 빨강과 다른 값이다. 테스트로 묶었다.
- **`tone.md` 2절 "예외 — 시세의 등락 색 짝"**: 강조색·오류 빨강과 따로 센다. 부호를 함께 쓴다. 칠하는 곳은 등락액·등락률·손익이다. 주문 버튼 색은 두 갈래(매수 빨강·매도 파랑, 또는 강조색 채움·옅은 면)다. 오류 빨강을 상승에 쓰지 않는다. 레퍼런스의 밝은 값은 대비가 모자란다.
- **`screen-conventions.md` "증권·투자" 절**: 틀(GNB 검색 칸, 본문 열 + 오른쪽 열), 홈, 종목 상세(머리 한 줄, 주문 패널은 1440 첫 화면 안, 호가 행 이름), 표 값(오른쪽 정렬·`tabular-nums`·행 40~48·글자 14, 빽빽한 표는 "가장 많은 글자 16"의 예외), 내 자산·관심·거래 내역·설정, 검색, 좁은 화면(하단 고정 판매·구매), 하지 말 것.
- **`SKILL.md`**
  - 3단계 화면 유형에 증권, 4단계에 등락 색, 6단계 예시에 증권 사이트를 넣었다.
  - 금지선 3행을 더했다: 주문 패널을 첫 화면 밖으로, 시세를 오류 빨강·밝은 값·색만으로, 보이는 글자와 다른 `aria-label`.
  - 값 표에 등락 색과 시세 표를 더했다. 체크리스트에 1항목을 더했다.
  - 10단계에 "편집 후 검사는 편집 도구로 쓸 때만 돈다. 셸로 쓰면 끝에 통합 검사를 직접 돌린다"를 적었다.
- **`layout-audit` `hue-count`**(TDD, 테스트 2개): 이름에 rise·fall·up·down 등이 든 변수의 색은 계열 수에서 뺀다. 1차 일반 쪽 산출물에서 등락 변수만으로 3계열이 되던 2곳의 경고가 사라졌다. 5계열을 쓴 곳은 그대로 경고한다.
- **평가**: 트리거 2개, `layout-principles` 선택 2개(461/461).
- **2차 뒤에 더한 것(재측정하지 않음)**
  - 아이콘 채움의 안쪽 선(TDD, 테스트 2개). 2차의 두 실행 모두 하단 탭 "내 자산"에 가방 아이콘을 채워 썼는데, 손잡이·윗선이 채움에 묻혀 검은 사각형으로 보였다. 판정 모델도 이것을 짚었다. 채운 모양에서 집의 문·가방 손잡이를 `--icon-cutout`(기본 흰색)으로 외곽 뒤에 그리게 고쳤다.
  - 검색 화면의 입력칸 중복. 2차의 한 실행이 GNB 검색 칸과 검색 화면 본문 입력칸을 함께 둬, 판정에서 졌다. "검색 화면의 입력은 GNB 칸 하나"를 관례에 적었다.
- **패턴 56개, 테스트 633개(정적 개수), 버전 0.10.0.**

### 블라인드 판정

| 판정 모델 | suta : 일반 | 순서를 바꿔도 같은 결론인 짝 |
|---|---|---|
| 기본 모델(화면을 만든 모델과 같다) | 23 : 5 | 14쌍 중 11쌍 |
| 다른 모델 | 24 : 4 | 14쌍 중 12쌍 |

비김은 없었다. 화면별로는 관심 종목·설정이 두 모델 모두 4:0, 검색이 두 모델 모두 2:2였다.

- **suta를 고른 이유**: 지수 요약 → 순위 표 → 내 자산·관심 종목으로 이어지는 위계, 열 머리가 있는 표, `▲▼`와 부호, 일정한 간격, 모바일의 하단 고정 매수·매도. 일반 쪽은 데스크톱 카드 높이가 어긋나 빈 곳이 생기거나, 모바일 하단 탭 아이콘이 깨지고, 업종 목록이 길게 늘어진다는 지적을 받았다.
- **일반을 고른 이유**
  - 검색(2:2): suta 한 실행이 검색 입력칸을 둘 두고, 결과 행에서 코드와 가격이 어긋났다.
  - 종목 상세 1번: 일반 쪽 주문 패널에 수수료·총 결제 금액이 있었고, suta 쪽 주 버튼이 수량을 넣기 전이라 비활성으로 보였다.
  - 기본 모델의 나머지 2번: 홈(일반 쪽 지수 차트·업종 히트맵이 더 풍부하다), 내 자산(suta 쪽 하단 탭의 검은 덩어리 아이콘).
  - 다른 모델의 나머지 1번: 거래 내역(suta 쪽 본문 폭이 GNB와 어긋나고, 매수·매도가 금액에서 드러나지 않는다).
- 퍼블리싱 벤치마크(단일 화면 16개)에서는 같은 판정 모델이 32번 중 11번, 다른 모델이 19번 suta를 골랐다. 이번 여러 화면 사이트에서는 두 모델 모두 suta 쪽으로 기울었다. 다만 짝은 14개(판정 28번씩)뿐이고, 일반 쪽은 1차 4번 중 처음 2번만 짝지었다.

## 6. 한계

- 실행은 조건마다 2번(일반은 4번)이다. 같은 조건에서도 화면 구조가 달라진다. 표의 구조 항목은 2번 모두 같은 쪽으로 간 것만 "개선"으로 읽는다.
- CLI 기본 모델 하나로만 만들었다. 판정 모델 하나는 화면을 만든 모델과 같다.
- 앱 레퍼런스는 종합 금융 앱 하나의 주식 탭(2022년)이다. 로그인해야 보이는 웹 화면(내 자산·거래 내역·호가)은 웹 레퍼런스에 없다.
- 2차 뒤에 고친 두 가지(아이콘 안쪽 선, 검색 입력 하나)는 다시 돌려 확인하지 않았다.
- 등락 색 관례는 국내·해외 둘만 다뤘다. 시장마다 다른 관례(일본 등)는 보지 않았다.
- 에이전트가 셸로 파일을 쓰면 편집 후 검사가 돌지 않는 문제는 안내만 더했다. 훅이 셸 쓰기를 잡게 바꾸지는 않았다.

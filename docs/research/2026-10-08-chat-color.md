# 실사용 점검 — 색의 수와 AI 채팅 화면

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-10-08 |
| 계기 | NoodleLens(Chrome 사이드 패널 AI 채팅 도구)에 suta를 적용한 결과(Guksu/NoodleLens PR #3)에 대한 사용자 평가 |
| 반영 | `skills/suta/SKILL.md`, `layout-principles`(tone.md·screen-conventions.md·principles.md·토큰), `layout-audit`(색 규칙 2개) |

## 1. 무엇이 문제였나

사용자 평가는 네 가지였다.

- 레이아웃은 나아졌지만 UI 구조가 아직 난잡하다.
- 불필요한 색 버튼이 있다.
- AI 슬롭에 자주 나오는 색(연노랑·주황·쨍한 초록)이 남아 있다.
- 실제 서비스에 쓰기에는 부족하다.

PR #3 전후 캡처(`docs/images/*.png`, 6b8b63e → 651fa95)를 나란히 놓으면 화면이 거의 같다. suta가 바꾼 것은 숫자뿐이었다. 글자 크기 11종을 4종으로, 반경 12종을 3종으로 줄이고, 4px 격자 밖 간격 119곳과 회색 하나의 대비를 고쳤다. 구조와 색은 그대로 남았다.

### 남은 구조

- 위에 고정된 줄이 3개다(모델, 사이트, 대상).
- 같은 대상을 대상 줄과 입력창 첨부 줄 두 곳에 보인다.
- "요소 선택" 입구가 3곳이다(빈 화면 버튼, 입력창 버튼, 대상 줄 아이콘).
- API 키 안내가 두 번(안내 상자, 입력창 아래), 로고가 두 번 나온다.
- 오류는 분홍 상자 안에 흰 알약 버튼이다.
- 보조 버튼(요소 선택·저장·복사·다시 시도)이 모두 회색 채움 알약이다.

### 남은 색

- 색 토큰이 34개였다. 노랑(브랜드·요소 표시), 주황(주의), 초록(정상), 파랑(정보·링크·포커스), 빨강(오류)이 있었다.
- 상태마다 옅은 바탕 짝(`-bg`)이 있었다.
- 제공자 아바타에 색이 달랐다(주황 C, 초록 G).

### suta 쪽 원인

1. 절차 1·3이 "이미 있는 체계가 우선, 색 체계가 있으면 그것을 쓴다"였다. 에이전트는 기존 팔레트와 구조를 그대로 두었다. 기존 화면을 고칠 때의 절차가 없었다.
2. 통합 검사는 CSS 값만 본다. error 0·warn 0이 곧 "완료" 신호가 됐다.
3. `tone.md`가 회색 채움 상자를 보조 버튼에 쓰라고 권했다.
4. 색 금지선은 "근거 없는 파랑"만 겨냥했다. 색의 수, 옅은 색 면, 상태 색 알약에 대한 기준이 없었다.
5. 화면 유형 관례 13종에 AI 채팅이 없었다.

## 2. 색 실측 — 잘 만든 앱은 색을 거의 쓰지 않는다

### 방법

- **표본**: designus 앱 레퍼런스 31곳, 서비스마다 36장, 모두 1,116장이다.
  - 로그인하지 않으면 서비스마다 앞쪽 36장만 보인다. 그래서 시작 안내·가입·소셜 로그인 화면이 많다.
  - 원본 이미지는 스크래치패드에만 두고 저장소에 넣지 않았다.
- **세는 픽셀**: 같은 색이 가로로 12px 이상 이어지는 픽셀만 센다(채널 차이 3 이내). 버튼·바탕·띠·알약 같은 UI 면이 남는다. 색이 계속 바뀌는 사진·일러스트와 런이 짧은 글자는 거의 빠진다. 점·작은 배지까지 보는 4px 런도 따로 쟀다.
- **유채색 판정**: 채널 차이 20 이상, 채도 0.15 이상. 계열은 HSL 색상각 8구간으로 나눴다(빨강·주황·노랑·초록·청록·파랑·보라·분홍).
- **서비스의 "체계 색"**: 그 서비스 화면 4장 중 1장 이상에 나오는 유채색 계열(화면 면적 0.2% 이상).
- **옅은 색 면**: 명도 0.88 이상인 유채색이 화면 면적 0.3% 이상.

### 결과

| 잰 것 | 잘 만든 앱 |
|---|---|
| UI 체계 색이 2종 이하인 서비스 | 31곳 중 25곳(81%) |
| 체계 색이 0~1종인 서비스 | 19곳(61%) |
| 옅은 색 면이 있는 화면 | 13%(파랑 5.6%, 주황 3.1%, 빨강 2.2%, 노랑 1.7%, 초록 1.0%) |
| 옅은 색 면을 화면 15% 이상에 쓰는 서비스 | 6곳(파랑 2, 주황 2, 노랑 1, 빨강 1) |
| 색 배지가 없는 화면(이전 화면 기록 1,110장) | 79% |
| 채운 버튼 0개 / 1개인 화면(이전 화면 기록) | 65% / 30% |
| 보조 행동 모양(이전 화면 기록에 나온 횟수) | 글자 버튼·링크 116 · 윤곽선 버튼 53 · 회색 채움 버튼 20 |

- 체계 색이 3종 이상인 6곳(올리브영·벅스·치지직·말해보카·플레이윙즈·오일나우)은 상품·앨범·방송·일러스트 같은 콘텐츠 색이 많은 서비스다.
- 주황·초록·노랑이 체계 색인 서비스는 그것이 브랜드색이다. 당근·직방·닥터나우는 주황, 스타벅스·잔디는 초록, KB국민기업카드는 노랑이다.
- 결론: **UI의 색은 무채색 + 브랜드색 하나 + 오류 빨강이다.** 주황·노랑·초록 자체가 문제가 아니다. 브랜드가 아닌데 상태 표시로 고른 색과 옅은 바탕 짝이 AI가 만든 화면의 표시다.

### 같은 방법으로 잰 NoodleLens

패널 화면 9장 기준이다. 페이지 위 강조 캡처는 뺐다.

| | PR #3 전 | PR #3(suta 0.6) | 이번(바뀐 suta 절차) |
|---|---|---|---|
| 화면당 유채색 계열(평균 / 최대) | 1.3 / 3 | 1.3 / 3 | 0.3 / 1 |
| 옅은 색 면이 있는 화면 | 6 / 9 | 6 / 9 | 0 / 9 |
| 패널에 나온 계열 | 빨강·주황·초록·파랑 | 빨강·주황·초록·파랑 | 빨강(오류) |

로고의 노랑은 면적이 0.1% 아래라 계열로 세지 않았다.

## 3. AI 채팅 화면의 관례

### 근거

- **공개 구현 두 가지의 코드**
  - Vercel Chat SDK 템플릿(`vercel/ai-chatbot`)
  - assistant-ui의 기본 화면과 ChatGPT·Claude 재현 화면(`assistant-ui/assistant-ui`, `apps/docs/.../examples/chatgpt.tsx`·`claude.tsx`)
- **이전 앱 화면 기록의 채팅 화면**: 에이닷 AI 캐릭터 채팅, 잔디 대화방, 당근 채팅방, 클로바 답변 화면.
- designus는 로그인하지 않으면 채팅 화면까지 보이지 않아, 이번에 새로 받은 표본에는 채팅 화면이 없다.

### 공통 관례

| 무엇 | 공개 구현 | 앱 기록 |
|---|---|---|
| 머리 | 한 줄(48~64px), 모델 선택·새 대화·메뉴. 테두리 없음 또는 얇은 선 | 뒤로 + 이름 + 아이콘 2~3개 |
| 대화 열 | 가운데 한 열, 최대 704~896px, 메시지 사이 20~32 | 같은 사람이 이어 보내면 4~13, 사람이 바뀌면 9~25 |
| 내 말 | 오른쪽 말풍선. `bg-muted`(옅은 회색) 또는 거의 검정, 모서리 16~22, 최대 70~80% | 오른쪽, 강조색 채움(에이닷 파랑) 또는 연한 면 |
| 답변 | 말풍선 없는 본문. 아바타 없음 또는 무채색 28px 하나 | 왼쪽 흰 말풍선 |
| 답변 동작 | 무채색 아이콘 버튼(24~32px). 마지막 답변만 늘 보이거나 hover 때만 | — |
| 입력창 | 아래 고정 상자 하나. 모서리 16~28, 얇은 무채색 테두리, 그림자 없음 또는 아주 옅음 | 흰 알약 또는 회색 알약, 안에 아이콘·전송 |
| 채운 버튼 | 보내기 하나(28~36px 원·둥근 네모, 강조색). 입력이 비면 회색 | 전송 아이콘만 강조색 |
| 빈 상태 | 인사 한 줄(24~36px) + 입력창, 제안 0~5개(윤곽선 칩·글자 목록) | 날짜·안내를 입력창 바로 위에 회색 작은 글자로 |
| 오류 | 토스트, 또는 옅은 빨강 상자 하나(assistant-ui). 다시 시도는 동작 줄의 아이콘 | — |
| 테마 색 | 모든 토큰이 무채색. 유채색은 `destructive`와 차트뿐 | 브랜드색 하나 |

suta에 넣을 때 한 가지를 고쳤다. 공개 구현의 오류 상자(옅은 빨강 면)는 "옅은 색 면" 기준과 부딪히고, NoodleLens에서 사용자가 지적한 분홍 상자와 같다. 그래서 "답변 자리의 빨강 아이콘 + 글자 + 글자 버튼"으로 정했다.

## 4. 반영

- `SKILL.md`
  - 1단계: 기존 체계는 값의 출처일 뿐, 금지선에 걸리는 색·구조는 고친다.
  - 새 2단계 "덜어내기": 같은 정보 두 곳, 같은 행동 입구 여럿, 고정 줄 여럿, 색 배지·알약·아바타, 유채색 수.
  - 4단계: UI 유채색은 강조색 하나 + 오류 빨강.
  - 금지선: 레이아웃 3행(회색 채움 알약, 정보·입구 중복, 고정 줄 쌓기), 글자·색·면 3행(옅은 색 면, 상태마다 색, 색 아바타). 상태 행은 분홍 상자까지 금지.
  - 값 표: 상태 색에서 주의를 빼고 "UI 색 수" 행 추가.
  - 체크리스트: 3항목 추가. "검사가 깨끗해도 구조는 직접 확인"을 명시.
- `tone.md`: 2절 "색의 수"(위 실측) 신설. 회색 채움을 보조 버튼에서 뺐다. 상태 색은 오류·완료만 남겼다.
- `screen-conventions.md`: 14번째 유형 "AI 채팅(대화형 도우미)", 사이드 패널 좁은 폭 포함.
- 토큰: `--color-warning`(주황)을 뺐다. `--color-success`는 글자에만 쓴다.
- `layout-audit`
  - 새 규칙 `tinted-surface`: 옅은 유채색 바탕. 판정은 OKLCH 밝기 0.9 이상, 채도 0.012 이상이다. 푸른 회색은 0.014 미만이면 회색으로 둔다.
  - 새 규칙 `hue-count`: 한 파일에 유채색 계열 3종 이상.
  - 예외 주석을 단 줄은 파일 단위 요약에서도 뺀다.
- 패턴 기본값: `loading-button`의 기본 파랑(#2563eb)을 거의 검정으로, `search-suggest`의 연파랑 선택 바탕을 회색으로 바꿨다.

## 5. 한계

- 색 실측은 앞쪽 36장(시작 안내·가입 흐름 중심)이다. 목록·상세 화면의 색은 이전 화면 기록(1,116장)의 글 기록으로 보충했다.
- 12px 런 측정은 평평한 일러스트·배너를 UI 면으로 센다. 서비스 단위 "체계 색"(화면 4장 중 1장)으로 우연을 줄였지만 완전히 빼지는 못한다.
- ChatGPT·Claude 실제 화면은 로그인이 필요해 직접 재지 않았다. 그 화면을 재현한 공개 코드의 값을 썼다.
- `hue-count`는 파일 단위다. 색을 여러 파일에 나눠 정의하면 각 파일은 통과할 수 있다.

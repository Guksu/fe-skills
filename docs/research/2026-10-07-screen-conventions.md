# 화면 유형별 관례 — 앱 화면과 웹사이트 분석

| 항목 | 내용 |
|------|------|
| 날짜 | 2026-10-07 |
| 방법 | ① 디자인 레퍼런스로 공유된 국내 앱 31곳의 화면 1,116장을 고정 형식으로 기록하고 화면 유형별로 집계했다. ② 레퍼런스로 공유된 웹사이트 19곳의 계산된 스타일을 데스크톱·모바일 폭에서 쟀다. ③ 같은 19곳의 공개 CSS에 suta 검사기를 돌렸다(→ 2절) |
| 상태 | 반영 완료. `layout-principles`에 화면 유형별 관례를 더했고, 편집 후 훅은 바꾼 줄만 판정하게 했다. 출처(사이트·서비스 이름)와 화면 이미지는 남기지 않는다 |

## 1. 한눈에

- **잘 만든 앱의 화면은 유형마다 뼈대가 거의 정해져 있다.** AI는 어떤 화면이든 같은 틀(히어로 → 카드 3장 → 버튼)로 짜는 경향이 있다. 잘 만든 앱은 화면 유형마다 다르게 짠다.
  - 홈: 구역 제목 + 가로로 넘기는 줄을 반복하고, 하단 탭을 둔다.
  - 상세: 사진 → 이름·가격 → 하단 고정 바.
  - 설정: 왼쪽 라벨 · 오른쪽 값의 행을 반복한다.
- **강조는 정말로 한 곳이다.** 채운 버튼이 1개 이하인 화면이 95%다. 카드 안에 카드를 넣은 화면은 4%뿐이다. 묶음을 나누는 첫째 수단은 간격(47%)이고, 그다음이 옅은 띠(19%)와 얇은 선(18%)이다.
- **주 행동은 화면 아래에 고정한 바 하나에 모은다.** 주 행동이 있는 화면에서 하단 고정의 비율은 아래와 같다(서비스 평균).
  - 시작 안내 90%, 폼 65%, 상세 63%.
  - 거래가 목적인 상세(구매·주문·예약·지원)는 15장 모두 하단 고정이었다.
- **지금 토큰은 측정 범위 안에 있다.** 좌우 여백 16/20/24, 주 버튼 높이 43/49/56, 데스크톱 본문 16px이다. 토큰을 바꿀 근거는 없었다.
- **검사 규칙은 늘리지 않고 훅의 소음을 줄였다.**
  - 잘 만든 웹사이트의 CSS에서도 예전 훅은 아무 줄 하나를 고칠 때 편집의 59%를 막았다.
  - 이번 편집이 바꾼 줄만 판정하게 바꾸자 0.9%로 줄었다.
  - 새 규칙 후보 4개는 오탐이 커서 기각했다(→ 6절).

## 2. 방법과 한계

### 자료

- **앱 화면**
  - 디자인 레퍼런스 사이트의 앱 화면 모음을 썼다. 국내 서비스 31곳이고, 서비스당 132~1,609장(중앙값 305장), 모두 12,944장이다.
  - 서비스마다 흐름 전체에서 고르게 44곳을 짚어 36장씩, 모두 1,116장을 뽑았다.
  - 앞쪽 36장만 쓰면 온보딩·가입에 치우쳐서(서비스 하나는 36장 모두 가입·로그인이었다) 이 방식으로 바꿨다.
  - 단계 이름만 적힌 구분 카드 44장은 픽셀 규칙(상태 표시줄 없음, 가운데 띠에만 글자)으로 걸러 바로 다음 화면으로 대신했다.
  - 앱 화면이 아닌 12장(외부 앱 화면·전환 중 캡처 등)은 집계에서 뺐다. 집계는 1,104장이다.
- **웹사이트**
  - 같은 레퍼런스 사이트의 웹 목록(좋아요순) 23곳에서, robots.txt가 허용한 19곳만 열었다.
  - 봇 확인 화면이 뜬 1곳은 풀지 않고 뺐다.
  - 데스크톱(1440px)·모바일(390px) 폭에서 보이는 요소의 계산된 스타일을 쟀다.
  - 글자가 10개 미만으로 잡힌 사이트(그림·영상 위주)는 수치 통계에서 뺐다. 그래서 데스크톱 15곳, 모바일 17곳이다.
- **수집 예절**
  - 페이지 사이 3초 이상 쉬었다. 사이트 설정에 드러난 API 키는 쓰지 않았다.
  - 원자료(이미지·CSS)는 세션 임시 폴더에만 두고 분석 뒤 지웠다.

### 기록 형식(앱 화면)

화면 한 장을 JSON 한 줄로 기록했다. 서비스 하나는 Sonnet 에이전트 하나가 맡았다.

| 무엇 | 항목 |
|---|---|
| 유형 | 홈·목록·격자·상세·검색·결제·폼·설정·빈 상태·시작 안내·시트·특수 화면(영상·채팅 등) |
| 구조 | 위→아래 블록 순서, 묶는 수단(간격·선·띠·카드)의 순위, 카드 사용과 중첩 |
| 행동 | 채운 버튼 수, 주 행동의 위치(하단 고정·내용 중간)·폭·높이·아래 여백, 보조 행동 |
| 막대 | 상단 바 종류, 하단 탭 유무·칸 수 |
| 위계 | 강한 강조 수, 색 배지 수, 글자 단계 수, 가장 큰 글자의 역할, 정렬 |
| 수치 | 좌우 여백, 구역 사이, 목록 행 높이, 사진 비율·모서리 |
| 원칙 | P1~P12를 분명히 따르거나 어긴 것 |

pt 값은 기기 폭을 390pt로 보고 캡처 픽셀에서 환산했다.

### 한계

- **수치는 눈대중이다.** 에이전트가 이미지를 보고 추정했고, 일부는 픽셀을 재서 보정했다. 기기 폭 가정 때문에 ±5% 안팎의 오차가 있다.
- **판정은 한 번만 했다.** 같은 화면을 두 에이전트가 기록해 맞춰 보지 않았다. 유형 경계(상세·특수 화면, 폼·시트)는 판정이 갈릴 수 있다.
- **국내 앱 중심이다.** 커머스·금융·커뮤니티·생활 서비스가 많다. 결제 화면(17장)과 격자(28장)는 근거가 적다.
- **비율은 서비스 평균이다.** 화면이 많은 서비스 하나가 결과를 끌고 가지 않도록, 서비스마다 비율을 낸 뒤 평균했다. 60% 이상을 "관례", 30~60%를 "흔한 선택"으로 부른다.
- **검사 적중률은 사이트 전체를 묶은 CSS 기준이다.** 컴포넌트 파일 하나보다 종류 수·효과 수가 크게 나온다(→ 6절).

### 3.2 유형별

비율은 서비스 평균이다. "주 행동"은 하단 고정이나 내용 중간에 주 버튼이 있는 화면을 뜻한다.

| 유형 | 표본 | 뼈대 | 핵심 측정 |
|---|---|---|---|
| 홈 | 65장 · 27곳 | 로고·왼쪽 큰 제목 → 배너·바로가기 → [구역 제목 + 가로로 넘기는 줄] 반복 → 하단 탭 | 하단 탭 70%(5칸이 4칸의 약 4배) · 가로 줄 67% · 구역 제목 왼쪽 64%(오른쪽 전체보기 18%) · 카드 51% |
| 목록 | 148장 · 29곳 | 상단 바 → 탭·칩·정렬 줄 → 같은 규격 행 반복 | 왼쪽 정렬 86% · 칩 23% · 행 구분 간격 36%·선 33% · 행 높이 70/100/135 |
| 격자 | 28장 · 13곳 | 탭·칩 → 2~3열 같은 칸 → 칸 안은 사진 위·글 아래 | 간격으로 묶음 61% · 칩 27% · 1:1 다음 2:3 |

| 검색 | 47장 · 25곳 | 상단 바 = 검색창 → 최근·추천 검색어 → 결과(종류 탭·정렬) | 검색창 상단 바 51% · 칩 18% · 결과 행 64/72/79 · 하단 탭 2% |

| 설정 | 61장 · 24곳 | 구역 라벨 → [왼쪽 라벨, 오른쪽 값·스위치·꺾쇠] 행 반복 | 왼쪽 정렬 83% · 꺾쇠 70% · 구역 제목 왼쪽 74% · 행 48/50/59 · 주 행동 버튼 15% |

### 3.3 서비스 에이전트들이 공통으로 적은 관찰

- 보조 행동을 낮추는 방식은 서비스마다 같았다. 윤곽선 버튼, 글자 버튼, 회색 채움, 아이콘이다. 되돌릴 수 없는 행동만 빨강을 쓴다.
- 입력 전 주 버튼은 "같은 자리·같은 크기의 회색"으로 둔다. 버튼을 숨기거나 옮기지 않는다.
- 키보드가 올라오면 하단 버튼이 키보드 바로 위로 올라간다.
- 가로로 넘기는 줄은 다음 카드를 화면 끝에서 잘라 보인다.
- 금액은 오른쪽 끝에 맞추고, 같은 역할의 행은 같은 높이로 반복한다.
- 결과가 없어도 검색창과 조건은 그대로 둔다. 빈 상태는 원래 자리의 제목·탭 아래에 들어간다.

### 훅 소음 — 예전과 지금

줄바꿈이 있는 CSS 22개 파일에서, 선언 한 줄(10,573줄)을 하나씩 고쳤다고 놓고 훅 응답을 셌다.

| | 막음(종료 2) | 알림(warn) |
|---|---|---|
| 예전 훅(파일 전체 판정) | 파일의 59.1% | 31.8% |
| 지금 훅(바꾼 줄만 판정) | 편집의 0.9% | 6.7% |

예전 훅은 잘 만든 사이트에서도 에이전트를 자주 멈췄다. 파일에 원래 있던 문제 때문이다. 지금 훅은 이번 편집이 바꾼 줄에 걸린 지적만 돌려보내고, 원래 있던 error는 한 줄로만 알린다. 요약 지적(척도 밖 간격·종류 수 등)은 관여한 줄 중 하나가 바뀌었을 때만 알린다.

### tiny-text 보정

- 아이콘 글꼴 선택자(`icon`·`fa-`·`material-icons` 등)는 글자가 아니라서 뺐다.
- `rem`은 `html`·`:root`의 글자 크기로 환산한다. 루트를 62.5%로 둔 사이트에서 `1.2rem`은 12px이지 19.2px이 아니다.
- 배지·라벨의 10px 글자는 잘 만든 사이트에도 있다. 그래도 error를 유지한다. AI가 흔히 만드는 `text-[10px]`·9px 보조 글자를 막는 것이 목적이다. 감수할 자리는 예외 주석으로 이유를 남긴다.

### 기각한 새 규칙 후보

| 후보 | 결과 | 이유 |
|---|---|---|

## 1. 방법

실제 사용자가 suta를 설치하고 요청하는 상황을 그대로 만들었다.

- **프로젝트**: `npm create vite`(React + TypeScript) 직후의 빈 프로젝트.
  - 상품 사진 12장을 `public/images`에 넣었다. 위키미디어 커먼즈의 국수 사진이고 CC0·CC BY·CC BY-SA다.
  - 사진과 출처는 실험 폴더에만 두고 저장소에는 넣지 않았다.
- **요청문**: 사용자 문장 그대로에 네 줄을 붙였다.
  - 이 프로젝트에 만들고, 화면 사이 이동이 되게 한다.
  - 국수 밀키트 쇼핑몰이고, 사진은 `public/images`에 있다.
  - 데이터는 목 데이터로 둔다.
  - `npm run build`가 통과해야 한다.
- **실행**: `claude -p`(CLI 기본 모델)를 썼다. 퍼블리싱 벤치마크(`scripts/benchmark/run.mjs`)와 같은 조건이다.
  - 편집 자동 승인, Bash 허용.
  - 조건 사이에 다른 것은 플러그인(`--plugin-dir`) 하나뿐이다.
- **평가**
  - 화면: 빌드한 결과를 390px(기기 배율 2, 터치)로 캡처했다. 한글 글꼴은 Pretendard로 맞췄다.
  - 검사: suta 통합 검사, axe-core(WCAG A·AA), 320px 넘침.
  - 색: 화면 요소의 계산된 색(글자·바탕·테두리·SVG)을 계열로 셌다. 사진은 뺐다. 지난번의 평평한 면 실측은 음식 사진이 섞여 이번에는 쓰지 않았다.
  - 구조: 레퍼런스 관례 항목을 코드와 화면에서 확인했다.

## 2. 1차 결과 — suta 0.7

| | 일반 Claude | suta 0.7 |
|---|---|---|
| 시간·비용 | 2.3분 · 0.39달러 | 4.6분 · 1.00달러 |
| suta 검사 | error 2 · warn 6 | error 0 · warn 0 |
| axe 위반(6화면) | 색 대비 111곳 | 1곳(가로 넘김 영역 초점) |
| UI 색 계열 | 주황(강조색)이 모든 화면 | 갈색 강조색 + 할인 빨강 |
| 아이콘 | 이모지(🏠 🍜 🛒 👤 🌶 🧊 ⚙️) | 손으로 그린 SVG — 설정 톱니가 해 모양 |
| 상품 카드 | BEST·NEW·인기 주황 알약 | 할인율 빨강만 |

suta는 색·대비·검사에서는 이미 일반보다 낫다. 하지만 실제 쇼핑 앱과 나란히 놓으면 구조가 비어 있었다.

- **홈**: 검색 입구가 없다. 로고·사진 한 장·칩 세 개·가로 줄 둘로 끝난다.
- **GNB**: 홈·상품·장바구니·마이 4칸이다.
  - 장바구니 화면에서 탭 바(56)와 주문 바(72)가 겹쳐 쌓였다.
  - 개수 배지는 원 없이 갈색 숫자만 떠 있다.
- **상세**
  - 머리에 뒤로만 있다.
  - 수량 스테퍼가 본문 맨 끝에 있다.
  - 후기·탭이 없다. 하단 바는 찜 + 담기다.
- **장바구니**: 상세에서 띄운 "담았어요 · 보러 가기" 토스트가 장바구니 화면까지 따라온다.
- **마이**: 이름·주문 단계 3칸·메뉴 3줄뿐이다. 이메일 자리에 사용자의 실제 이메일이 들어갔다. 세션에 보이는 계정 정보다.
- **설정**: 로그아웃이 어디에도 없다.
- **패턴 코드**: 복사한 `quantity-stepper`의 포커스 링이 기본값 `#2563eb` 파랑 그대로다. 프레임워크 기본 파랑을 막는 suta가 그 색을 기본값으로 가지고 있었다.
- **확인**: 두 조건 모두 "브라우저가 없어 화면을 직접 보지 못했다"고 끝냈다.

### suta 쪽 원인

1. 화면 관례에 "하단 탭을 어느 화면에 두는가"가 없었다. 홈에 "하단 탭 4~5칸" 한 줄뿐이었다.
2. 상세 관례가 음식 주문 상세(수량을 가격 옆에) 기준이었다. 쇼핑 상품 상세(옵션·수량은 구매 시트)와 커머스 홈·마이의 관례가 없었다.
3. 아이콘은 "한 벌로"라고만 했다. 쓸 아이콘이 없으니 에이전트가 그때그때 그렸다.
4. 패턴 13개의 기본 강조색이 프레임워크 파랑(`#2563eb`·`#1d4ed8`)이었다. `switch`의 켜짐 색은 iOS 초록 `#34c759`였다.
5. 웹뷰 고유 함정(안전 영역·높이 단위·입력칸 확대·확대 막기)과 이모지 아이콘을 검사하는 규칙이 없었다.

## 3. 레퍼런스 — 하단 탭 바와 커머스

지난번에 기록한 앱 화면 1,116장(31곳)을 다시 집계했다. 커머스 3곳(뷰티·패션·공동구매)의 화면 62장을 따로 읽었다.

### 하단 탭 바

| 화면 유형 | 탭 바가 있는 비율 |
|---|---|
| 홈 | 62% |
| 목록 | 34% |
| 격자 | 32% |
| 설정·마이 | 21% |
| 장바구니·주문 | 6% |
| 상세 | 5% |
| 검색 | 4% |
| 폼 | 1% |

- 칸 수는 5칸이 107화면, 4칸이 28, 3칸이 17이다.
- 현재 탭만 강조색(또는 검정)의 채운 아이콘과 굵은 라벨이다. 나머지는 회색 선 아이콘이다.
- 배지는 빨강 원이나 빨간 점이다.
- 토스트·떠 있는 버튼은 탭 바 위에 뜬다.
- 커머스 3곳은 모두 5칸이고, 모두 장바구니를 탭이 아니라 머리 오른쪽 아이콘(개수 배지)에 둔다.

### 커머스 화면

- **좌우 여백**: 12~17이다(중앙값 15~16). 일반 화면(20)보다 좁다.
- **홈**
  - 세 곳 모두 검색 입구가 맨 위에 있다(아이콘 또는 둥근 회색 검색창).
  - 그 아래 순서: 카테고리 글자 탭 → 배너 캐러셀(현재/전체 표시) → 바로가기 아이콘 → 구역 제목 + 가로 상품 줄.
- **상품 카드**
  - 사진 1:1(패션 5:6)에 찜 하트를 얹는다.
  - 그 아래 순서: 이름 2줄 → 할인율 빨강 + 판매가 굵게(정가 취소선) → 별점·후기 수 회색 → 회색 윤곽선 태그.
  - 품절은 같은 자리에 회색 덮개를 씌운다.
- **상세**
  - 머리는 뒤로 + 홈·장바구니다.
  - 가격 묶음에서는 판매가가 가장 크다.
  - 배송 행 → 8px 띠 → 탭(상품정보·후기·문의)이 이어진다.
  - 하단 고정 바는 찜 + 구매다. 옵션은 시트에서 고른다.
- **마이**
  - 맨 위는 프로필(등급 링크)이다.
  - 그 아래 순서: 쿠폰·포인트·후기 수치 → 주문 단계 4~5칸(큰 숫자 + 꺾쇠) → 메뉴 묶음 → 로그아웃 → 회사 정보.

### 2차에서 드러난 패턴 버그

1. **`BottomNav.tsx`가 자기 CSS를 불러오지 않았다.**
   - 다른 패턴의 React 래퍼는 `import './{패턴}.css'`를 직접 한다.
   - A는 문서의 사용 예시에 있던 CSS 불러오기를 빠뜨렸다. 그래서 탭 바가 스타일 없이 화면 가운데에 목록으로 그려졌다.
   - 래퍼가 CSS를 불러오게 고쳤다.
2. **`bottom-sheet`의 시트 안 버튼이 마우스·터치로 눌리지 않았다.**
   - 시트를 누르는 순간 `setPointerCapture`를 해서, 크롬이 뒤따르는 click을 시트로 넘겼다. B의 "장바구니 담기"를 눌러도 아무 일이 없었다(키보드로는 된다).
   - 8px 움직인 뒤에 끌기로 보고 그때 포인터를 잡게 고쳤다(TDD).
   - B의 앱에 고친 파일만 넣었더니 장바구니에 담겼다. suta 데모에서 끌어서 닫기도 그대로 동작한다.

두 버그 모두 에이전트가 "브라우저가 없어 화면을 보지 못했다"고 끝낸 실행에서 나왔다. 정적 검사(error 0)로는 잡을 수 없었다.

## 6. 한계

- 실행은 조건마다 1~2번이다. 0.7 재실행만으로도 구조가 달라질 만큼 편차가 있다. 표의 항목은 0.8 네 번이 모두 같은 쪽으로 간 것만 "개선"으로 읽는다.
- CLI 기본 모델 하나로만 돌렸다. 다른 모델에서는 결과가 다를 수 있다.
- 커머스 레퍼런스는 3곳 62장이다. 로그인하지 않으면 보이는 화면만이라, 결제 이후 화면은 적다.
- 구조 항목(검색 입구·구매 시트·마이 구성)은 사람이 레퍼런스 관례와 대조해 판정했다.
- 에이전트가 화면을 직접 보지 못하는 문제는 그대로다. suta는 정적 검사로 보완하지만, 렌더해야 보이는 버그(CSS 누락·클릭이 안 먹는 버튼)는 남는다.

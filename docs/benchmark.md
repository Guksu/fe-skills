# 퍼블리싱 벤치마크 — 일반 Claude Code와 suta

같은 요청문을 두 Claude Code에 그대로 주고, 만든 화면을 브라우저로 열어 쟀습니다.

- **일반**: 아무것도 설치하지 않은 Claude Code
- **suta**: suta 플러그인(진입 스킬 + 편집 후 검사 훅)만 설치한 Claude Code

모델·설정·도구 권한은 두 쪽이 같습니다. 다른 것은 플러그인 하나뿐입니다.

English: [benchmark.en.md](benchmark.en.md)

## 결과 (2026-10-07 · 조건마다 화면 16개)

### 한눈에

- **결함은 suta 쪽이 크게 적었습니다.**
  - 접근성 위반(axe)은 16개 화면 합계 87건 → 4건입니다. 일반 쪽 87건 중 81건이 글자 대비 부족이었습니다.
  - 상자 안 상자(41 → 0), 그라데이션·흐림·큰 그림자(47 → 0), 24px 미만 터치 영역(27 → 0)이 모두 0이 됐습니다.
  - 12px 미만 글자가 있는 화면(4 → 0), 320px에서 옆으로 밀리는 화면(2 → 0)도 0이 됐습니다.
  - 글자 크기 종류는 화면당 8.1 → 4.1로 절반입니다.
- **차이가 없던 것도 있습니다.** 두 쪽 모두 `transition: all`을 쓰지 않았습니다. 동작 줄이기 대응은 움직임이 있는 일반 쪽 화면 15개 중 14개가 이미 했습니다.
- **블라인드 판정은 일반 쪽을 더 많이 골랐습니다.** 판정 32번 중 기본 판정 모델은 25번, 다른 판정 모델은 18번 일반 쪽을 골랐습니다.
  - suta 쪽이 진 이유는 "깔끔하지만 밋밋하다"가 가장 많았습니다(아래 [판정 이유](#판정-이유)).
  - suta 쪽은 일반 쪽에 눈에 띄는 결함이 있을 때 이겼습니다. 깨진 막대그래프, 어절 중간에서 끊긴 제목 등입니다(대시보드·랜딩).
- **비용이 더 듭니다.**
  - 시간은 화면 하나에 중앙값 61초 → 96초입니다.
  - 입력 토큰은 4.3배, 출력 토큰은 1.5배입니다. 스킬과 패턴 문서를 읽고 검사를 돌리기 때문입니다.

### 판정 이유

판정자가 남긴 한 문장 이유를 모으면 이렇습니다.

- **일반 쪽을 고른 이유**
  - 설정 화면을 회색 바탕 위 카드로 묶어 구역이 뚜렷했다(suta는 선으로만 나눠 "평평하다").
  - 소셜 로그인 버튼에 브랜드 색과 아이콘이 있었다(suta는 모두 같은 흰 버튼).
  - "비밀번호 찾기" 같은 링크가 파란색이라 링크로 보였다(suta는 회색 글자).
  - 장바구니의 전체 선택·선택 삭제처럼 기능이 더 많았다.
  - 데스크톱에서 모바일 열을 회색 바탕 위 가운데 틀에 놓았다(suta는 흰 바탕에 좁은 열만 놓여 "덩그러니").
- **suta 쪽을 고른 이유**
  - 일반 쪽에 마감 결함이 있었다: 막대그래프가 그려지지 않음, 축 라벨 줄바꿈, 제목이 어절 중간에서 끊김, 섹션 제목이 카드 테두리에 걸침, 글머리표가 여백 밖으로 나옴.
  - suta 쪽은 왼쪽 정렬·간격이 일관되고 핵심 수치가 가장 컸다.

### 스킬 사용

- suta 조건 16회 모두 스킬을 읽었습니다. 요청문에는 suta를 언급하지 않았습니다.
- 많이 읽은 패턴은 `layout-principles`·`motion-principles`(각 13회), `quantity-stepper`(6회), `toast-stack`(4회)입니다.
- 편집 후 검사 훅은 warn을 6번 돌려보냈고, error로 막은 적은 없습니다.
- 권한 때문에 거절된 도구 호출은 두 조건 모두 0건입니다.

### 해석 — suta가 고칠 것

결함을 줄이는 일(접근성·좁은 화면·작은 글자·상자 중첩·효과 남발)은 의도대로 작동했습니다. 판정에서 진 이유는 대부분 덜어내기가 지나친 곳입니다. 다음 개선 후보입니다.

- 설정처럼 묶음이 많은 화면은 회색 바탕 위 묶음 목록(inset grouped)이 관례다 — "상자는 마지막 수단"의 예외로 둔다.
- 브랜드 지침이 있는 버튼(소셜 로그인)은 "강조는 한두 곳"의 예외다.
- 링크는 링크처럼 보여야 한다(색이나 밑줄).
- 넓은 화면에 모바일 한 열을 놓을 때는 바탕과 틀로 열의 경계를 보인다.
- 요청에 없는 기능을 빼라는 뜻이 아니다 — 덜어낼 것은 장식이지 기능이 아니다.

## 방법

### 요청문 8개

화면 유형마다 하나씩, 실무에서 흔히 쓰는 말투로 썼습니다. 전문은 [`evals/benchmark/prompts.json`](../evals/benchmark/prompts.json)에 있습니다.

| id | 화면 유형 | 요청(요약) |
|---|---|---|
| `menu-detail` | 상세 | 카페 앱 메뉴 상세 — 사진, 이름·가격, 사이즈·샷 옵션, 수량, 담기 버튼 |
| `login` | 폼 | 로그인 — 이메일·비밀번호, 소셜 로그인 3개, 회원가입·비밀번호 찾기, 오류 상태 |
| `settings` | 설정 | 앱 설정 — 프로필, 알림 토글, 언어·테마, 로그아웃·탈퇴 |
| `dashboard` | 대시보드 | 판매자 대시보드 — 핵심 지표, 최근 주문, 주간 매출 막대그래프, 반응형 |
| `landing` | 랜딩 | 일정 관리 SaaS 랜딩 — 히어로, 기능 3개, 요금제 3단, FAQ, 푸터 |
| `cart` | 장바구니 | 장바구니 — 상품(수량·삭제), 쿠폰, 결제 금액, 주문 버튼 |
| `search-results` | 목록 | 맛집 검색 결과 — 검색창, 필터 칩, 결과 목록, 결과 없음 상태 |
| `option-sheet` | 인터랙션 | 옵션 바텀시트(끌어서 닫기)와 담김 토스트, 자연스러운 애니메이션 |

모든 요청 끝에 같은 문장을 붙였습니다. "결과는 현재 폴더의 index.html 한 파일로. CSS와 JS는 그 안에, 외부 라이브러리·CDN·이미지 파일은 쓰지 않는다." 산출물을 같은 조건에서 재기 위해서입니다.

### 실행

- 요청 하나를 조건마다 2번씩 돌렸습니다(8 × 2 × 2 = 32회). 실행마다 빈 폴더에서 새 세션으로 시작합니다.
- `claude -p`(비대화형)로 돌렸습니다. 파일 쓰기는 작업 폴더 안에서 자동 승인하고, 셸 명령은 모두 허용했습니다. 사람이 옆에서 승인해 주는 것과 같게 하려는 것입니다. 비대화형에는 승인할 사람이 없어서, 허용하지 않은 호출은 그냥 거절됩니다. 두 조건이 같습니다.
- suta 조건은 `--plugin-dir`로 플러그인을 실었습니다. 마켓플레이스로 설치한 것과 같은 구성(매니페스트 + `skills/`)이고, 플러그인 폴더는 읽을 수 있게 열었습니다(`--add-dir`). 요청문에 suta를 언급하지 않았습니다 — 스킬이 스스로 걸리는지도 지표입니다.
- 권한 때문에 거절된 도구 호출 수를 실행마다 기록했습니다. 처음에는 셸을 읽기 명령만 허용했는데, suta 쪽이 패턴 문서와 검사기를 읽지 못하고 끝났습니다. 그래서 위 설정으로 바꿔 32회를 모두 다시 돌렸습니다.

### 측정

산출물(`index.html`)을 Chromium으로 열어 렌더된 값으로 쟀습니다. 측정 코드는 suta의 검사기와 따로 썼습니다.

| 지표 | 재는 법 |
|---|---|
| 320px 가로 넘침 | 320px 폭에서 문서가 옆으로 스크롤되는가 |
| 12px 미만 글자 | 390px 폭에서 글자를 직접 가진 요소의 계산된 글자 크기 |
| 24px 미만 터치 영역 | 링크·버튼·입력의 상자 중 짧은 변이 24px 미만(문장 안 링크는 뺌, 체크박스·라디오는 라벨까지) |
| 카드형 상자 | 둥근 모서리 + (테두리 · 둘레와 다른 바탕 · 그림자)인 요소 수. 버튼·입력·이미지, 48×32px보다 작은 것, 원·알약 모양, 이름이 컨트롤인 것(아바타·칩·토글·세그먼트 등)은 뺌. 많고 적음이 곧 좋고 나쁨은 아니라 설명용으로만 봄 |
| 상자 안 상자 | 카드형 상자가 또 카드형 상자 안에 있는 수 |
| 그라데이션·흐림·큰 그림자 | 넓은 그라데이션 배경, `backdrop-filter`, 흐림 16px 이상 그림자, 그라데이션 글자인 요소 수 |
| 글자 크기 종류 | 보이는 글자의 계산된 크기 종류 수 |
| 가운데 정렬 문단 | 두 줄 이상인 글 덩어리 중 가운데 정렬인 것 |
| `transition: all` | 계산된 `transition-property`가 `all`이고 시간이 0보다 큰 요소가 있는가 |
| 레이아웃 속성 애니메이션 | 너비·높이·위치·여백을 움직이는 전환이나 `@keyframes`가 있는가 |
| 동작 줄이기 대응 | 움직임이 있는 화면에 `prefers-reduced-motion` 규칙(CSS 또는 스크립트)이 있는가 |
| 접근성 위반 | [axe-core](https://github.com/dequelabs/axe-core) 4.14 — WCAG 2.0·2.1·2.2 A·AA 규칙. 심각도 serious·critical을 따로 셈 |
| suta 검사 | 같은 파일에 suta의 레이아웃·모션 검사(`skills/suta/scripts/audit.mjs`)를 돌린 결과. suta가 스스로 정한 기준이라 참고로만 봄 |

처음 열린 상태만 잽니다. 바텀시트처럼 눌러야 열리는 부분의 모양은 지표에 들어가지 않습니다. 다만 움직임 지표는 계산된 스타일과 스타일시트 전체를 보므로 닫혀 있는 요소도 셉니다.

### 블라인드 판정(참고)

같은 요청·같은 회차의 두 화면 스크린샷(모바일 390px 전체, 데스크톱 1280px 첫 화면)을 A·B로만 보여 주고 고르게 했습니다.

- 판정자는 플러그인 없는 새 Claude Code 세션입니다. 화면을 만든 것과 같은 모델(기본 판정 모델)로 한 번, 다른 모델로 한 번 판정했습니다.
- 기준은 "숙련된 프로덕트 디자이너가 그대로 내보내도 좋다고 할 쪽"입니다. suta의 규칙은 알려 주지 않았습니다.
- 모바일 전체 화면 캡처에서는 화면에 고정된 요소(상단 바·하단 버튼 바)를 스크롤 끝·처음에 보이는 자리로 옮겨 찍었습니다. 그대로 찍으면 하단 바가 페이지 한가운데에 찍혀 내용을 가린 것처럼 보입니다. 처음 판정은 이 문제가 있는 캡처로 했고, 고친 뒤 다시 했습니다.
- 한 쌍을 순서를 바꿔 두 번 판정했습니다. 앞에 놓인 쪽을 고르는 버릇을 상쇄하기 위해서입니다.
- 사람의 평가가 아니라 모델의 판정입니다.

## 한계

- **표본이 작습니다.** 요청 8개 × 2회입니다. 차이가 작은 지표는 우연일 수 있습니다. 실행별 값은 [`evals/benchmark/results.json`](../evals/benchmark/results.json)에 모두 있습니다.
- **모델 하나, 설정 하나**입니다. 다른 모델이나 생각 수준에서는 결과가 다를 수 있습니다.
- **지표 일부는 suta가 막는 것과 겹칩니다**(상자 안 상자, `transition: all` 등). suta가 주장하는 효과를 suta 검사기와 다른 코드로 재 본 것이라는 뜻입니다. 접근성(axe)은 제3자 기준입니다.
- **처음 상태만** 봅니다. 상호작용 뒤의 화면과 실제 동작(끌어서 닫기가 손을 따라오는지 등)은 재지 않았습니다.
- **판정은 모델의 취향**입니다. 기본 판정 모델은 화면을 만든 모델과 같아서, 자기가 평소 만드는 모습을 더 좋게 볼 수 있습니다. 그래서 다른 모델로 한 번 더 판정했고, 두 결과의 차이가 큽니다(32번 중 일반 쪽을 고른 횟수가 25번과 18번). 사람 디자이너의 평가는 하지 않았습니다.
- 판정자는 데스크톱 첫 화면만 봅니다. 그래서 "하단 바가 마지막 행을 가린다"는 이유 일부는 스크롤하면 풀리는 것이었습니다(끝까지 내린 상태를 잰 지표에서는 두 조건 모두 0건).
- 한 파일 HTML이라는 조건은 실무(React 등)와 다릅니다. 같은 조건에서 비교하려고 고정했습니다.

## 다시 돌리기

claude CLI를 32번 부르므로 시간과 사용량이 듭니다(동시 4개로 약 30분).

```bash
npm i --no-save playwright axe-core && npx playwright install chromium
node scripts/benchmark/run.mjs --out ../suta-bench --repeats 2 --concurrency 4   # 실행(중간에 끊겨도 같은 명령으로 이어서)
node scripts/benchmark/measure.mjs --out ../suta-bench                          # 측정
node scripts/benchmark/judge.mjs --out ../suta-bench                            # 블라인드 판정(선택)
node scripts/benchmark/report.mjs --out ../suta-bench                           # 집계 → evals/benchmark/results.json
```

작업 폴더는 저장소 밖의 짧은 경로가 좋습니다. 모델이 긴 경로를 옮겨 적다 틀리면, 작업 폴더 밖 쓰기로 막혀 산출물이 없는 실행이 생깁니다.

# 설계: fe-skills — 프론트엔드 애니메이션/UI/UX 스킬 저장소

## 1. 목표와 완료 기준

프론트엔드 애니메이션·UI·UX 구현 지식을 **에이전트가 읽고 바로 구현할 수 있는 스킬**로 축적하는 저장소.
각 스킬은 (1) 사용 방법 (2) 사용 예시 코드 (3) 사람이 눈으로 확인하는 UI 데모를 갖춘다.

**스킬 1건의 완료 기준(게이트):** ① demo 빌드·린트 통과 ② 스킬 구조 검증(frontmatter·링크) 통과 ③ 브라우저에서 데모 실동작 확인(스크린샷/녹화) ④ fe-craft 모션 리뷰(이징·타이밍·reduced-motion) 통과 ⑤ 워크로그 기록.
**첫 릴리스 완료 기준:** 스킬 1~2개가 위 게이트를 통과하고, 플러그인이 마켓플레이스로 설치 가능하며, 데모 사이트가 GitHub Pages에 배포됨.

## 2. 범위

**포함:**

- 플러그인 골격(marketplace.json·plugin.json) + 첫 스킬 2개: enter-exit(진입/퇴장), scroll-reveal(스크롤 리빌) — 문서+references+assets 예시 컴포넌트
- Vite+React 데모 SPA(스킬별 데모 페이지, assets 컴포넌트 import 렌더링) + GitHub Pages 배포(Actions)
- 하네스(라이트): 도메인 스킬 1개(스킬 추가 파이프라인) + 훅·권한 + 템플릿 2종 + CLAUDE.md 포인터

**제외:**

- npm 패키지 배포, Storybook, 저장소 분리
- 에이전트 정의·오케스트레이터(풀 티어 산출물 — 대량 작업이 생기면 확장 분기로 승격)
- 애니메이션 카테고리 전체 커버(첫 릴리스는 구조 검증용 1~2개만)

## 3. 시스템 구조

- 저장소: https://github.com/Guksu/fe-skills (현재 로컬 remote는 envault.git으로 오설정 — 교체 필요)
- 현재 상태: 빈 디렉토리, 커밋 0건
- 사용자 컨벤션(기존 단일 출처): useCallback/useMemo 지양, 화살표 함수, named-object 인자, useEffect 명명, TDD 우선, 한글 조판 word-break: keep-all

**저장소 레이아웃 (2라운드 확정):**

```
fe-skills/
├─ .claude-plugin/marketplace.json   # 마켓플레이스 카탈로그 — 플러그인 2개 등록
├─ plugins/
│  ├─ ui/                            # fe-ui 플러그인 (UI/애니메이션)
│  │  ├─ .claude-plugin/plugin.json
│  │  └─ skills/{skill-name}/
│  │     ├─ SKILL.md                 # 정본: 사용 방법·사용 예시
│  │     ├─ references/              # 상세 문서
│  │     └─ assets/                  # 예시 컴포넌트 코드 (정본의 일부)
│  └─ system/                        # fe-system 플러그인 (시스템 설계 — 문서+문답)
│     ├─ .claude-plugin/plugin.json
│     └─ skills/{skill-name}/
│        ├─ SKILL.md                 # 문답 절차 + 추천 종합 방법
│        └─ references/              # 케이스별 설계 트레이드오프 문서
├─ demo/                             # Vite+React SPA — UI 스킬만 노출, 설치 안 됨
│  └─ src/demos/{skill-name}/        # plugins/ui/skills/*/assets/를 import해 렌더링
└─ docs/                             # 설계·워크로그
```

- 데모는 GUI 쇼케이스 — 스킬 문서(및 assets/ 예시 코드)가 정본, 데모 앱은 그 코드를 import해 보여주기만 한다(복사본 금지)
- 기술 기준: CSS 우선, CSS로 어려운 것만 라이브러리(motion 등) — 스킬마다 "왜 이 기술인가" 한 줄 명시
- 프레임워크 지원(5라운드): assets = 바닐라 코어(.ts, 의존성 0) + React 래퍼(.tsx) 2층. 순수 JS·React 프로젝트 모두 사용 가능해야 한다
- 데모 배포: GitHub Pages (GitHub Actions, main 푸시 시 자동)

## 4. 실행 방식과 역할

- **실행 모드: 직접 실행** — 반복 작업이 "스킬 추가"(문서→데모→검증) 순차 흐름 하나뿐. 병렬화·협상 요소 없음 → 사다리 0단.
- **티어: 라이트** — 도메인 스킬 `add-skill`(가칭) 1개 + 훅·권한 + 규칙 파일 + 템플릿 2종(worklog·handoff). 에이전트 정의·오케스트레이터는 만들지 않는다.
- UI 구현·수정 시 `fe-craft`(모션 리뷰·디자인 비평), 데모 사이트 배포 전에는 `fe-predeploy`를 연결한다.

## 5. 안전장치와 권한

- 보호 브랜치: **main**. 작업은 feat/{skill-name} 브랜치에서(branchGuard 훅).
- PR 플로우 **옵트인 활성**(allowCommitPush=true): 사용자가 명시 요청 시에만 커밋·푸시·PR 생성(pr 스킬, PR 베이스 main). 머지·rebase·force push는 사용자 전담. 커밋·PR에 Claude 작성 표기 금지(훅 차단).
- 훅 3종: git 변경 차단 · 시크릿 접근 차단 · 보호 브랜치 편집 차단 + 시크릿 deny 권한.
- 검증 게이트는 §1 완료 기준 참조. 단위 테스트는 로직 있는 예시(상태 전이·제스처)에만 적용 — 순수 시각 애니메이션에 빈 테스트를 양산하지 않는다.

## 6. 문답 기록

| 라운드 | 주제 | 결정 |
|--------|------|------|
| 1 | 목표·범위·완료 기준 | 배포=Claude Code 플러그인 마켓플레이스 / 데모=Vite+React SPA / 첫 릴리스=스킬 1~2개로 구조 검증 / 하네스 범위=스킬 추가 + 데모 사이트 운영 |
| 2 | 도메인·구조·제약 | 레이아웃=plugin/+demo/ 분리(루트 marketplace.json, plugin/만 설치 범위) / 정본=스킬 문서(데모는 GUI 쇼케이스, 예시 컴포넌트는 plugin/skills/{skill}/assets/에 두고 데모가 import — 복사본 없음) / 기술 기준=CSS 우선·필요 시 라이브러리 / 데모 배포=GitHub Pages(Actions 자동 배포) |
| 3 | 실행 방식·역할·안전장치 | 티어=라이트(도메인 스킬 1개, 에이전트·오케스트레이터 없음) / git=main+feat, PR 플로우 옵트인(allowCommitPush, PR 베이스 main, 머지는 사용자) / 검증 게이트=demo 빌드+린트 통과 → 스킬 구조 검증 → 브라우저 실동작 확인(스크린샷/녹화) → fe-craft 모션 리뷰 통과 / 단위 테스트는 일괄 강제하지 않고 로직 있는 것(상태 전이·제스처)만 |
| 4 | 최종 확인 | 첫 스킬 2개=진입/퇴장 애니메이션(enter-exit) + 스크롤 리빌(scroll-reveal) / 설계 승인 → 구축 착수 |
| 5 | 프레임워크 지원 범위(구축 후 보완) | 스킬 assets는 **바닐라 코어 + React 래퍼** 2층 구조 — 코어는 프레임워크 무관 TS(DOM API로 data 속성 구동), React 래퍼가 코어를 사용. 전부 TS로 통일하고 JS 프로젝트 복사 시 타입 제거를 SKILL.md에 안내. 초기 구축이 React 전용이었던 것을 사용자 지적으로 교정 |
| 6 | 데모 브랜드(2026-08-22) | 레퍼런스 앱(토스·당근·인스타 등)은 참고만 — 데모 UI의 문구·탭 이름·구성은 fe-skills 고유 브랜드(국수집 테마)로 쓴다. 레퍼런스 언급은 SKILL.md 관례 설명까지만 |
| 7 | 뷰/로직 분리(2026-08-24) | 저장소를 **플러그인 2개 모노레포**로 확장: `plugins/ui`(fe-ui — 기존 16종) + `plugins/system`(fe-system — 프론트엔드 시스템 설계, 신규). 별도 레포 분리는 보류(하네스·마켓플레이스 공유 이득, 분리는 되돌리기 쉬운 결정). 시스템 스킬은 **문서+문답 중심**: 케이스별 설계 트레이드오프 문서 + 실행 시 플랫폼·기능 문답 → 에이전트 종합 추천. 데모 페이지는 UI 스킬만 노출. 시스템 스킬 게이트는 구조·트리거 검증(브라우저·데모 게이트 제외) |

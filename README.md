## AS-IS / TO-BE

아래 요청들을 Claude Code에 맡겼습니다. 한쪽은 아무것도 설치하지 않았고, 다른 쪽은 suta만 설치했습니다. 모델과 설정은 같습니다.

### 모바일 웹뷰: 이커머스

> 모바일 웹뷰에 사용하는 이커머스 화면들을 구현해줘. 홈 / 상품 리스트 / 상품 상세 / 마이 페이지 / 장바구니 / 설정 / GNB가 있어야 해

![위 줄은 suta 없이(AS-IS), 아래 줄은 suta를 설치하고(TO-BE) 만든 쇼핑 앱 화면. 왼쪽부터 홈, 상품 리스트, 상품 상세, 장바구니, 마이, 설정](docs/assets/as-is-to-be.jpg)

왼쪽부터 홈, 상품 리스트, 상품 상세, 장바구니, 마이, 설정입니다. 390px 폭에서 찍었습니다. 음식 사진의 출처는 [이미지 출처](docs/assets/CREDITS.md)에 있습니다.

suta 없이는 한 번, suta 0.8로는 네 번 실행했습니다. 아래 줄은 네 번 중 세 번째 실행입니다. 표는 그림 속 두 줄을 비교합니다.

| | AS-IS (suta 없이) | TO-BE (suta 설치) |
|---|---|---|
| 색 | 주황을 배너·카테고리·배지·별점·버튼에 씀 | 갈색 강조색 하나. 할인율만 빨강 |
| 아이콘 | 이모지 | 같은 크기·같은 굵기의 선 아이콘 |
| 상품 카드 | BEST·NEW·인기 주황 알약 | 할인율, 가격, 별점만 |
| 홈 | 검색 입구가 없음 | 맨 위에 검색창 |
| 상세 하단 바 | 찜, 수량, 담기, 구매 버튼 4개 | 찜과 구매하기. 옵션과 수량은 구매하기를 누르면 올라오는 시트에서 고름 |
| 하단 탭(GNB) | 장바구니가 탭이라, 장바구니 화면에 탭과 주문 버튼이 함께 고정됨 | 장바구니는 머리 오른쪽 아이콘. 상세와 장바구니에서는 탭을 숨김 |
| 접근성 위반(axe, 6화면) | 색 대비 111곳 | 0곳 |

네 번 모두 같았던 것은 홈 검색창, 머리의 장바구니, 상세·장바구니에서 숨는 탭, 구매 시트, 선 아이콘 한 벌입니다. 강조색은 네 번 중 세 번이 짙은 초록이었고, 접근성 위반은 0\~2곳이었습니다. 만드는 시간은 2.3분에서 5\~7분으로 늘었습니다. 실험 방법과 실행별 결과는 [모바일 웹뷰 이커머스 연구](docs/research/2026-10-08-commerce-webview.md)에 있습니다.

### 데스크톱: 증권 플랫폼 웹사이트

> 증권 플랫폼 웹사이트를 구현해줘. 홈(시장 개요) / 종목 상세(차트·호가·주문) / 내 자산 / 관심 종목 / 검색 / 거래 내역 / 설정 / GNB가 있어야 해

![위 줄은 suta 없이(AS-IS), 아래 줄은 suta를 설치하고(TO-BE) 만든 증권 웹사이트. 왼쪽은 홈, 오른쪽은 종목 상세](docs/assets/securities-as-is-to-be.jpg)

왼쪽은 홈, 오른쪽은 종목 상세입니다. 1440px 폭의 첫 화면입니다. 종목 이름과 시세는 지어낸 데이터입니다.

suta 없이는 네 번, suta 0.10으로는 두 번 실행했습니다. 그림은 두 조건의 첫 번째 실행입니다. 표는 화면 7개를 잰 값입니다.

| | suta 없이 (4번) | suta 0.10 (2번) |
|---|---|---|
| 접근성 위반(axe, 1440px) | 63~277곳, 대부분 색 대비 | 0곳 |
| 상승 빨강 | `#e8383d` 등, 흰 바탕에서 4.1:1 | `#d0262d`, 4.5:1 이상 |
| 첫 화면 안의 주문 버튼 | 네 번 중 두 번 | 두 번 모두 |
| 머리의 검색 칸 | 네 번 모두 | 두 번 모두(`/` 단축키 표시) |
| 모바일 종목 상세의 하단 고정 판매·구매 | 없음 | 두 번 모두 |
| 만드는 시간·비용 | 3\~4.4분, 0.54\~0.75달러 | 7.4\~14.5분, 1.51\~1.72달러 |

화면마다 두 결과를 이름 없이 보여 주고 더 나은 쪽을 고르게 했습니다. 짝 14개를 순서를 바꿔 두 번씩, 모두 28번입니다. 화면을 만든 모델과 같은 판정 모델은 23번, 다른 판정 모델은 24번 suta를 골랐습니다. 검색 화면만 2:2였습니다. 짝이 14개뿐이라 이 숫자로 일반화하기는 어렵습니다.

처음 suta 0.9로 돌렸을 때는 색 대비는 맞췄지만, 주문 패널을 첫 화면 아래에 두고 머리에 검색 칸이 없었습니다. 증권 웹 10곳을 레퍼런스로 관례를 더한 것이 0.10입니다. 방법과 실행별 결과는 [증권 웹사이트 연구](docs/research/2026-10-09-securities-web.md)에 있습니다.

## 어떻게 동작하나

suta는 세 부분으로 되어 있습니다.

1. 진입 스킬(`skills/suta/SKILL.md`)은 에이전트가 UI 요청마다 읽는 지시문입니다. 작업 순서, 하지 말 것, 간격·글자·색 값이 들어 있습니다.
2. 패턴 56종(`skills/suta/patterns/`)은 바텀 시트, 하단 탭, 토스트 같은 UI의 설명서와 코드입니다. 에이전트는 필요한 패턴을 골라 코드를 프로젝트에 복사합니다. 런타임 의존성은 없습니다.
3. 편집 후 검사는 플러그인으로 설치했을 때만 돕니다. 파일을 고칠 때마다 레이아웃·모션 검사를 돌립니다. 에이전트는 방금 바꾼 줄의 문제만 돌려받고 고칩니다.

지시문과 설명서는 한국어로 썼습니다. 이름은 수타(手打)에서 왔습니다. 기계로 뽑은 면이 아니라 손으로 친 면처럼, 손으로 다듬은 UI를 목표로 합니다.

## 설치

Claude Code:

```text
/plugin marketplace add Guksu/suta
/plugin install suta@suta
```

Codex는 설치한 뒤 `/hooks`에서 suta의 편집 후 검사를 승인합니다.

```bash
codex plugin marketplace add Guksu/suta
codex plugin add suta@suta
```

Cursor, Gemini CLI, GitHub Copilot 같은 다른 에이전트에는 스킬만 설치합니다. 편집 후 검사는 돌지 않습니다.

```bash
npx skills add Guksu/suta --skill suta
```

설치 스크립트, 설치 폴더, 예전 버전에서 옮기는 방법은 [상세 안내의 "설치"](docs/guide.md#설치)에 있습니다.

## 쓰는 법

평소처럼 요청하면 됩니다. "로그인 화면 만들어줘"나 "이 버튼 애니메이션 다듬어줘"라고 하면, 에이전트가 suta를 읽고 맞는 패턴을 고릅니다.

패턴 56종은 [라이브 데모](https://guksu.github.io/suta/)에서 직접 만져 볼 수 있습니다. 목록은 [상세 안내](docs/guide.md#패턴-56종)에 있습니다.

## 벤치마크

화면 종류 8개(상세·폼·설정·대시보드·랜딩·장바구니·목록·인터랙션)의 요청을 두 쪽에 두 번씩 맡겼습니다. 만든 화면은 브라우저로 열어 쟀습니다. 아래는 suta 0.6.0으로 잰 2차 결과입니다.

| 화면 16개 (낮을수록 좋음) | 일반 Claude Code | suta 설치 |
|---|---|---|
| 접근성 위반 (axe, 합계) | 87 | 13 |
| 상자 안 상자 (합계) | 41 | 1 |
| 그라데이션·흐림·큰 그림자 (합계) | 47 | 0 |
| 24px 미만 터치 영역 (합계) | 27 | 0 |
| 12px 미만 글자가 있는 화면 | 4 | 0 |
| 320px에서 가로로 넘친 화면 | 2 | 0 |
| 주 버튼이 파랑·남색·보라 계열인 화면 | 10 | 0 |

suta 쪽에서 가장 많이 쓴 글자 크기는 16px입니다. 같은 방법으로 잰 레퍼런스 웹사이트의 중앙값과 같습니다.

모델에게 두 화면을 이름 없이 보여 주고 더 나은 쪽을 고르게 했습니다. 비김도 고를 수 있었습니다. 화면을 만든 모델과 같은 판정 모델은 32번 중 11번 suta를 골랐고, 다른 판정 모델은 19번 골랐습니다. 비김은 없었습니다. 두 판정이 갈렸으므로, 보기에 어느 쪽이 나은지는 이 숫자로 말할 수 없습니다.

화면 하나를 만드는 시간은 중앙값 61초에서 103초로 늘었습니다. 방법, 판정 이유, 한계는 [벤치마크 문서](docs/benchmark.md)에 있습니다.

## 무엇을 막나

AI 슬롭은 AI가 만든 티가 나는 결과물을 말합니다. suta는 에이전트가 UI를 만들 때 아래 금지선을 지키고, 패턴 56종의 코드를 가져다 쓰게 합니다.

| AI가 흔히 만드는 UI | suta를 쓰면 |
|---|---|
| 모든 화면이 같은 틀이고, 모든 섹션이 카드다 | 화면 유형마다 정해진 뼈대에서 시작하고, 간격과 얇은 선으로 묶는다 |
| 간격·글자·반경 값이 제각각이고, 9px 글자가 있다 | 값은 토큰(척도)에서만 고르고, 글자는 12px 이상이다 |
| 강조색이 프레임워크 기본 파랑이고, 상태마다 연노랑·주황·연두를 칠한다 | 강조색 하나와 오류 빨강만 쓴다 |
| 그라데이션·배지·채운 버튼이 곳곳에 있다 | 강조는 화면마다 한두 곳이다 |
| 이모지를 아이콘으로 쓴다 | 같은 크기·같은 굵기의 선 아이콘 한 벌을 쓴다 |
| `transition: all`을 붙이고 높이를 움직인다 | `transform`·`opacity`만 움직이고, 시간은 움직이는 크기에 맞춘다 |
| 키보드·스크린 리더·동작 줄이기 설정을 무시한다 | 모든 패턴이 접근성과 동작 줄이기에 대응한다 |

전체 목록은 [상세 안내의 "무엇을 없애나"](docs/guide.md#무엇을-없애나)에 있습니다.

## 한계

- 비교는 조건마다 한두 번 실행한 결과입니다. 같은 조건으로 다시 돌려도 화면 구조가 달라집니다.
- 규칙의 값은 국내 앱 31곳의 화면 1,104장과 레퍼런스 웹사이트 19곳에서 뽑았습니다. 다른 나라 서비스의 관례와는 다를 수 있습니다.
- 에이전트가 읽는 양이 늘어 시간과 비용이 늘어납니다. 이커머스 실험에서 2.3분·0.39달러가 5\~7분·1.35\~1.55달러가 됐습니다.
- 에이전트는 만든 화면을 직접 보지 못합니다. 정적 검사로는 렌더해야 보이는 버그(스타일을 불러오지 않은 컴포넌트, 눌리지 않는 버튼)를 잡지 못합니다.
- 실험은 Claude Code의 기본 모델 하나로만 돌렸습니다.

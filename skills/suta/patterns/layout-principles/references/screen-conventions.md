# 화면 유형별 관례

잘 만든 앱 화면을 유형별로 모아, 공통으로 보이는 뼈대와 값을 정리했다. 화면을 새로 짤 때는 그 유형의 뼈대에서 시작한다(P11 익숙한 구조에서 시작한다). 개성은 뼈대가 아니라 한 요소의 크기·사진·색으로 낸다.

- **근거**: 국내 앱 31곳의 실제 화면 1,116장이다. 서비스마다 첫 화면부터 마지막 화면까지 고르게 36장을 뽑아, 한 장씩 같은 형식으로 기록했다. 앱 화면이 아닌 12장은 집계에서 뺐다.
- **읽는 법**
  - "관례"는 그 유형의 화면이 있는 서비스들의 평균이 60% 이상인 것이다.
  - "흔한 선택"은 30~60%다.
  - 수치는 390pt 폭 화면 기준 pt이고, CSS px와 같다.
  - 수치가 셋이면 아래 사분위·중앙값·위 사분위다. 예: 44/50/56.
- 데스크톱 웹은 맨 아래 "넓은 화면" 절에 따로 둔다.

## 모든 화면에 공통

| 무엇 | 관례 | 측정 |
|---|---|---|
| 채운 버튼 | 화면마다 0~1개. 보조 행동은 윤곽선·글자 버튼·아이콘으로 낮춘다 | 1개 이하인 화면 95% |
| 묶는 수단 | 간격이 먼저다. 그다음이 옅은 배경 띠·얇은 선이고, 카드 안 카드는 드물다 | 1순위 간격 47% · 띠 19% · 선 18%, 카드 중첩 4% |
| 면 | 흰 면과 옅은 바탕 두 단계. 구역 사이 8px 띠, 회색 채움 상자, 회색 바탕 위 흰 묶음 중 하나 이상. 카드는 테두리·그림자 없이 톤 차이로 | 카드의 71%가 테두리·그림자 없음 · 띠 25곳 · 채움 상자 28곳 |
| 강조색 | 서비스마다 하나. 채운 면은 주 버튼, 같은 색을 선택 상태·밑줄·링크에 이어 쓴다(`references/tone.md`) | 채운 버튼 색이 서비스마다 다르다 |
| 좌우 여백 | 한 화면에 한 값. 16~24, 가장 흔한 값은 20 | 16/20/24 |
| 상단 바 | 하위 화면은 뒤로 + 제목, 최상위 화면은 로고나 왼쪽 큰 제목 | 뒤로 + 제목 48% |
| 정렬 | 왼쪽 정렬선 하나. 가운데 정렬은 빈 상태·시작 안내·팝업의 짧은 글에만 | 왼쪽 58% · 섞임 27% · 가운데 14% |
| 위계 | 가장 큰 글자는 화면 제목(금액이 목적인 화면은 숫자). 글자 크기는 2~3단 | 제목 76% · 3단 |
| 강한 강조 | 채운 색 면·그라데이션·큰 그림자·색 배지 묶음을 합쳐 1~2곳 | 1/1/2 |
| 주 버튼 | 높이 44~56. 하단 고정이면 폭 가득, 아래에 홈 표시줄 높이(안전 영역) + 8~16을 둔다 | 높이 43/49/56 · 바 아래 35/45/55 |
| 사진 | 1:1이 가장 흔하다. 한 목록은 한 비율, 모서리는 0이거나 8~12 | 1:1 > 16:9 > 2:1 · 모서리 7/12/20 |

## 유형별

### 홈(첫 화면·피드형)

- **뼈대**
  1. 상단: 로고 또는 왼쪽 큰 제목 + 아이콘 2~3개.
  2. 대표 배너 하나 또는 바로가기 줄.
  3. 구역을 반복한다: 왼쪽 굵은 구역 제목 → 가로로 넘기는 줄. 다음 카드를 화면 끝에서 잘라 보여 넘길 수 있음을 알린다.
  4. 하단 탭 4~5칸.
- **값**: 하단 탭 70%(5칸이 4칸보다 네 배 흔하다) · 가로 줄 67% · 구역 제목 왼쪽 64%(오른쪽에 전체보기 18%) · 구역 사이 16/36/50.
- **하지 말 것**
  - 구역마다 카드·그림자를 씌운다.
  - 모든 구역을 같은 격자로 반복한다.
  - 가로 줄을 화면 폭에 딱 맞춘다. 넘길 수 있다는 신호가 사라진다.
- **관련 패턴**: `carousel`, `tab-indicator`, `skeleton`, `pull-to-refresh`.

### 목록·피드

- **뼈대**
  1. 상단 바(뒤로 + 제목, 또는 아래에 큰 제목).
  2. 탭 줄·칩·정렬 한 줄.
  3. 같은 규격의 행을 반복한다(썸네일 + 2~3줄 글).
  4. 필요하면 오른쪽 아래에 떠 있는 + 버튼.
- **값**: 왼쪽 정렬 86% · 칩 23% · 행은 간격(36%)이나 얇은 선(33%)으로 나눈다 · 행 높이 70/100/135(썸네일 행 포함, 글만 있는 행은 48~60).
- **세부**
  - 정렬은 목록 바로 위 오른쪽 끝에 회색 작은 글자 + 화살표로 둔다. 목록보다 눈에 띄지 않게 한다.
  - 선택된 칩은 짙은 채움(흰 글자)이나 강조색 테두리·글자로 표시한다. 선택이 없어 보이는 칩 줄은 "아직 고르지 않음"으로 읽힌다.
  - 행 안 보조 정보(평점·거리·영업 상태)는 한 줄로 모은다. 상태는 상태 색 글자(영업 중은 초록, 마감은 옅은 글자)로 구분하고 배경 알약을 씌우지 않는다.
- **하지 말 것**
  - 행마다 카드를 씌운다.
  - 행마다 높이·순서가 다르다.
  - 금액을 왼쪽에 둔다(오른쪽 끝이 관례).
  - 사진 자리에 이모지를 넣는다. 사진이 없으면 같은 비율의 옅은 바탕 칸을 둔다.
- **관련 패턴**: `infinite-scroll`, `virtual-list`, `pull-to-refresh`, `swipe-to-delete`, `segmented-control`, `skeleton`.

### 격자(상품·앨범·선택 타일)

- **뼈대**: 탭·칩 → 2~3열 같은 크기 칸 반복 → 칸 안은 사진 위, 글 2~3줄 아래(왼쪽 정렬).
- **값**: 좌우 16/17/20 · 열 간격 8~15 · 사진 1:1이 가장 흔하고 2:3이 다음 · 칸 크기를 모든 칸에 같게 둔다 · 묶음은 간격 61%.
- **하지 말 것**: 칸마다 다른 비율의 사진, 칸 안 채운 버튼.
- **관련 패턴**: `skeleton`, `infinite-scroll`, `card-expand`.

### 상세(상품·가게·글·프로필)

- **뼈대**
  1. 상단 바: 뒤로 + 아이콘. 사진 위에 겹치기도 한다.
  2. 폭 가득 대표 사진.
  3. 이름과 가격. 가장 큰 글자는 대개 이름이고(74%), 판매가 목적인 화면은 가격을 가장 크게 두기도 한다.
  4. 핵심 정보 한 묶음.
  5. 탭 줄 또는 구역들.
  6. **하단 고정 바**: 보조(찜 아이콘·윤곽선 버튼) + 채운 주 버튼 하나.
- **값**
  - 주 행동이 있는 상세 화면의 63%가 하단 고정이고(화면 수로는 70%), 그중 71%가 폭 가득이다.
  - 구매·주문·예약·지원처럼 거래가 목적인 상세 화면은 주 행동이 있는 15장 모두 하단 고정이었다(서비스 10곳).
  - 버튼 높이 42/48/54 · 바 아래 34/42/46 · 보조 행동을 함께 두는 경우 40%.
  - 글·약관 같은 읽기 전용 상세에는 주 행동이 없다.
- **세부**
  - 가격은 이름 바로 아래에 둔다. 굵게, 본문의 1.5배 이상(24px 안팎)이다. 설명 뒤로 밀지 않는다.
  - 옵션은 그룹마다 굵은 제목 + 라디오 행이다. 그룹 사이는 얇은 선, 큰 구역(옵션·수량·추가 메뉴) 사이는 8px 옅은 띠로 나눈다.
  - 라디오는 선택된 것만 강조색 링 + 점이다. 나머지는 옅은 회색 윤곽선이다.
  - 수량은 가격과 한 줄에 둔다. 가격은 왼쪽 굵게, 스테퍼는 오른쪽 끝이다.
  - 하단 고정 버튼 글자에 금액을 넣는다(예: "12,000원 담기").
- **하지 말 것**: 담기·구매·찜을 모두 채운 버튼으로 내용 중간에 둔다. 스크롤하면 사라지고 강조가 셋으로 나뉜다.
- **관련 패턴**: `stretchy-header`, `zoom-lightbox`, `quantity-stepper`, `bottom-sheet`(옵션), `loading-button`, `like-pop`, `sticky-header`.

### 검색

- **뼈대**
  1. 상단 바가 곧 검색창이다. 알약 모양, 연회색 채움, 왼쪽 뒤로·오른쪽 취소 글자.
  2. 입력 전: 최근·추천 검색어(칩이나 목록).
  3. 입력 중: 연관어 목록.
  4. 결과: 종류 탭 → 정렬 줄 → 결과 목록.
- **값**: 검색창이 상단 바인 화면 51% · 결과 행 64/72/79 · 칩 18% · 하단 탭은 거의 없다(2%).
- **하지 말 것**: 결과가 없을 때 검색창과 조건을 지운다. 둘 다 남겨 바로 고칠 수 있게 한다.
- **관련 패턴**: `search-suggest`, `segmented-control`, `tab-indicator`.

### 장바구니·주문·결제

근거가 적다(17장, 서비스 9곳).

- **뼈대**
  1. 구역(배송지 → 상품 → 할인·결제 수단 → 결제 금액)을 굵은 회색 띠로 나눈다.
  2. 구역마다 왼쪽 굵은 제목으로 시작한다.
  3. 하단 고정 결제 버튼에 금액을 함께 적는다.
- **값**: 띠로 나눔 76% · 구역 제목 왼쪽 70% · 버튼 47/49/56 · 가장 큰 글자가 금액인 화면 35% · 선택된 결제 수단만 채운다.
- **장바구니 세부**
  1. 상단 바: 뒤로 + 가운데 "장바구니".
  2. 전체 선택 줄: 왼쪽 체크박스 + "전체 선택 (3/4)", 오른쪽 끝에 "선택 삭제" 글자 링크.
  3. 상품 행: 체크박스 → 정사각 썸네일(64~80px) → 이름(두 줄까지)·옵션(옅은 글자) → 오른쪽 위 삭제(×).
  4. 행 아래 줄: 왼쪽 수량 스테퍼, 오른쪽 끝 굵은 판매가. 할인이 있으면 정가(취소선, 옅은 글자)를 판매가 위에 둔다.
  5. 8px 띠 → 쿠폰 → 8px 띠 → 금액 요약. 라벨 왼쪽(보조 글자)·금액 오른쪽, 할인은 상태 색이나 강조색, 합계 줄만 굵게 키운다.
  6. 하단 고정 바: 폭 가득 주 버튼에 금액과 개수를 넣는다(예: "37,000원 주문하기").
- **하지 말 것**: 가격을 스테퍼와 떨어진 줄에 혼자 둔다. 헤더 개수와 보이는 상품 수가 다르다(첫 화면에 다 안 보이면 개수를 목록 위 전체 선택 줄에 둔다).
- **관련 패턴**: `quantity-stepper`, `checkbox-radio`, `loading-button`, `accordion`.

### 폼·로그인·인증

- **뼈대**
  1. 상단 바(뒤로).
  2. 질문형 굵은 제목(왼쪽, 1~2줄).
  3. 입력칸: 라벨이 위에 있고, 밑줄이나 옅은 채움 상자.
  4. 칸 바로 아래 한 줄 안내·오류.
  5. 하단 고정 폭 가득 버튼. 입력 전에는 같은 자리·같은 크기의 회색 비활성으로 둔다.
- **값**
  - 주 행동이 있는 폼의 65%가 하단 고정이고, 그중 92%가 폭 가득이다.
  - 버튼 47/50/56 · 입력칸·행 43/49/56 · 묶음 사이 23/36/45.
  - 키보드가 올라오면 버튼을 키보드 바로 위로 올린다.
- **로그인 세부**
  - 입력칸은 옅은 바탕 채움이나 밑줄이다. 라벨은 칸 위에 보조 글자로 둔다.
  - 주 버튼은 강조색으로 채운다.
  - 보조 이동(비밀번호 찾기·회원가입)은 글자 링크다. 밑줄이나 강조색 글자로 링크답게 보인다. 둘이면 가운데 한 줄에 세로선으로 나눈다.
  - 소셜 로그인 버튼은 서비스 고유 색과 로고를 쓴다(카카오 노랑, Apple 검정, Google·네이버는 흰 바탕 + 로고). 높이·폭·글자 위치를 같게 맞추고 8~16px 간격으로 쌓는다. 값은 `references/tone.md` 5절.
  - 오류는 해당 칸 바로 아래 한 줄(상태 색)과 칸 테두리로 알린다. 상태를 보여 주려고 화면에 미리보기 버튼을 두지 않는다.
- **하지 말 것**: 입력칸마다 카드를 씌운다, 라벨 없이 칸 안 안내 글만 둔다, 오류를 화면 위 토스트로만 알린다, 소셜 버튼을 모두 같은 흰 윤곽선으로 둔다.
- **관련 패턴**: `floating-label`, `form-shake-error`, `otp-input`, `select`, `wheel-picker`, `checkbox-radio`, `loading-button`.

### 설정·마이

- **뼈대**
  1. 상단 바(뒤로 + 제목) 또는 프로필 머리.
  2. 작은 회색 구역 라벨.
  3. 행을 반복한다: 왼쪽 라벨, 오른쪽 끝 값·스위치·꺾쇠.
  4. 구역 사이는 띠나 선.
- **값**: 행 48/50/59 · 꺾쇠 70% · 구역 라벨 55% · 왼쪽 정렬 83% · 구역 제목 왼쪽 74% · 주 행동 버튼이 있는 화면은 15%뿐이다.
- **면 — 두 방식이 흔하다.** 평평한 흰 목록에 선만 두지 않는다.
  1. 흰 바탕 + 구역 사이 옅은 띠. 띠(높이 8~40px) 안이나 바로 아래에 작은 옅은 구역 라벨, 흰 행은 왼쪽을 들인 얇은 선으로 나눈다.
  2. 옅은 바탕 + 흰 둥근 묶음. 묶음은 테두리·그림자 없이 `--radius-card`, 좌우 16px다. 구역 라벨은 묶음 밖 위에 옅은 글자로 둔다(라벨~묶음 8px, 묶음~다음 라벨 20~28px).
- **세부**
  - 오른쪽 끝 요소가 동작을 알린다. 꺾쇠는 이동, 현재 값 + 꺾쇠는 선택, 스위치는 켜고 끔, 값만 있으면 정보다.
  - 켜진 스위치·선택된 값만 강조색이다.
  - 프로필 머리는 원형 아바타 + 굵은 이름 + 옅은 이메일이다. 편집은 오른쪽 끝 작은 윤곽선 버튼이나 꺾쇠로 둔다.
  - 로그아웃은 일반 행과 같은 모양이다. 회원 탈퇴는 채운 빨강 버튼이 아니라 맨 아래 옅은 글자 링크로 낮춘다.
- **하지 말 것**: 행마다 카드를 씌운다. 고칠 수 없는 값에 꺾쇠를 단다. 구역 사이를 빈 공간(48px 이상)만으로 크게 벌린다.
- **관련 패턴**: `switch`, `select`, `accordion`, `segmented-control`.

### 빈 상태·결과 없음·완료

- **뼈대**
  1. 원래 자리의 제목·탭·검색창·조건은 그대로 둔다.
  2. 그 아래 남은 영역에 아이콘이나 일러스트 하나를 둔다.
  3. 굵은 한 줄 + 회색 설명.
  4. 버튼은 0~1개(윤곽선이나 하단 하나).
- **값**: 가운데 정렬 48%(섞임 41%) · 아이콘·안내 91% · 버튼 61% · 채운 버튼 1개 이하 100% · 위치는 내용 영역의 위쪽 1/4~가운데.
- **관련 패턴**: `enter-exit`, `skeleton`(불러오는 중과 구별).

### 시작 안내·권한

- **뼈대**
  1. 상단 바 없음.
  2. 가운데 큰 제목 + 그림이나 화면 목업 하나.
  3. 페이지 점(여러 장일 때).
  4. 하단 고정 폭 가득 버튼 하나. 그 위에 작은 고지를 둘 수 있다.
- **값**: 주 행동의 하단 고정 90% · 버튼 48/55/56 · 상단 바 없음 63% · 가운데 정렬 45% · 구역 사이 34/44/56.
- **기타**: 시스템 권한 창보다 먼저 목적을 설명하는 화면을 둔다.
- **관련 패턴**: `carousel`, `page-transition`, `story-progress`.

### 시트·팝업

- **바텀 시트**
  - 위 모서리 14~20.
  - 손잡이 또는 머리줄(닫기·제목·확정 글자)을 둔다.
  - 뒤 화면은 20~80% 어둡게 덮는다.
  - 선택 목록은 글자 행(42~62)으로 쌓는다.
- **대화상자**
  - 폭 270~290, 가운데에 둔다.
  - 제목 → 설명 → 버튼 둘을 같은 폭으로 둔다(취소는 왼쪽에 옅게, 실행은 오른쪽에 강조색).
  - 빨강은 되돌릴 수 없는 행동에만 쓴다.
- **값**: 뒤 화면을 어둡게 77% · 바텀 시트 47% · 대화상자 37% · 주 버튼 높이 43/48/55.
- **관련 패턴**: `bottom-sheet`, `modal-dialog`, `toast-stack`, `long-press-menu`, `dropdown-menu`.

### 대시보드(관리 화면)

앱 기록에는 없는 유형이다. 디자인 피드백 사례 14건에서 정리했다.

- **뼈대**
  1. 넓은 화면은 "왼쪽 메뉴 | 오른쪽 내용" 두 덩어리다. 좁은 화면은 메뉴를 상단 바의 메뉴 버튼이나 하단 탭으로 접는다.
  2. 내용 머리: 페이지 제목 + 기준 시각 + 필터·주 행동 하나. 카드로 싸지 않고 바탕 위에 바로 둔다.
  3. 핵심 지표 3~4개.
  4. 차트와 할 일·최근 목록.
- **면**
  - 페이지는 옅은 바탕이다. 흰 카드는 지표·차트·표 같은 데이터 묶음에만 쓴다(테두리·그림자 없이).
  - 메뉴는 카드로 띄우지 않는다. 바탕과 같은 톤이나 흰 면으로 가장자리에 붙인다.
- **세부**
  - 지표: 숫자는 이름의 2~3배로 키운다. 증감은 숫자 아래 작은 한 줄로 두고 상태 색 글자로 쓴다. 색 알약은 쓰지 않는다.
  - 왼쪽 메뉴의 글자는 세 단계다. 그룹 이름은 가장 옅고 작게, 1단계는 진하게, 하위는 한 단계 작고 옅게 둔다. 현재 항목은 옅은 강조색 바탕 + 강조색 글자다.
  - 차트: 강조색 한 색의 농도 차이로 그린다. 오늘·선택한 막대 하나만 진하게, 값은 막대 위나 옆에 적는다. 축 글자는 12px 이상이고 줄바꿈되지 않게 단위를 축 제목으로 뺀다.
  - 표·주문 목록: 행 높이를 하나로 통일하고 선 한 줄로 나눈다. 상태는 상태 색 글자로, 금액은 오른쪽 끝 같은 폭 숫자다.
- **하지 말 것**: 머리·메뉴·필터까지 모두 흰 상자로 띄워 조각낸다. 지표마다 다른 원색을 준다.
- **관련 패턴**: `segmented-control`, `tab-indicator`, `skeleton`, `count-up`.

### 랜딩(서비스 소개)

웹사이트 측정(아래 "넓은 화면" 절)과 디자인 피드백 사례 38건에서 정리했다.

- **뼈대**: 상단 바(로고 · 메뉴 · 주 행동 하나) → 히어로(제목 · 한두 줄 설명 · 주 버튼 + 보조 버튼, 오른쪽에 제품 화면 하나) → 기능 → 요금 → 자주 묻는 질문 → 푸터.
- **세부**
  - 히어로의 메시지는 하나다. 제목은 생각보다 크게 잡는다. 데스크톱 48~64px, 모바일 32~40px이다.
  - 섹션 제목은 히어로 제목보다 한 단계 확실히 낮춘다.
  - 같은 크기 상자만 반복하지 않는다. 큰 모듈 하나와 작은 모듈 여럿을 섞어 리듬을 만든다. 기능 4개 안팎은 "번호 + 제목" 한 열과 얇은 선으로도 충분하다.
  - 구역마다 면을 바꿔 리듬을 만든다. 흰 구역과 옅은 바탕 구역을 번갈아 쓴다.
  - 요금제는 같은 규격 열로 두고, 추천 하나만 강조색 테두리나 채운 버튼으로 구별한다.
  - 강조색은 주 버튼·링크·추천 요금제에만 쓴다.
- **하지 말 것**: 제목 위에 메뉴를 반복하는 작은 알약 라벨을 단다. 기능 카드마다 색 아이콘 원을 깐다. 그라데이션 글자를 쓴다.
- **관련 패턴**: `accordion`(자주 묻는 질문), `glass-nav`, `scroll-reveal`, `segmented-control`(월·연 결제).

### AI 채팅(대화형 도우미)

ChatGPT·Claude 같은 범용 AI 채팅 화면이다. 공개 구현 두 가지와 앱 기록의 채팅 화면에서 정리했다.

- **근거**
  - Vercel Chat SDK 템플릿과 assistant-ui(기본 화면, ChatGPT·Claude 재현 화면)의 코드에 있는 값.
  - 앱 기록의 채팅 화면: 에이닷 AI 캐릭터 채팅, 잔디·당근 대화방, 클로바 답변 화면.
- **뼈대**
  1. 머리 한 줄(높이 48~64): 모델 선택 · 새 대화 · 기록(또는 메뉴). 테두리 없이 바탕과 같은 면이다. 다른 정보 줄을 머리 아래에 쌓지 않는다.
  2. 대화 열: 가운데 한 열, 최대 폭 704~768(44~48rem). 메시지 사이 20~32.
  3. 아래 고정 입력창 하나: 입력 · 첨부 · 보내기. 대화가 비어 있으면 인사 문구 바로 아래에 둔다.
- **메시지**
  - 내 말: 오른쪽 정렬 말풍선. 바탕은 옅은 회색(`--color-canvas`), 모서리 16~22, 최대 폭 70~80%. 강조색으로 채운 말풍선은 브랜드색이 분명할 때만 쓴다.
  - 답변: 말풍선 없는 본문이다. 대화 열 폭 그대로, 본문 크기·행간 1.5~1.65. 아바타는 없거나 무채색 작은 아이콘 하나다. 모델별 색 원은 쓰지 않는다.
  - 답변 동작(복사·다시 생성·좋아요): 답변 아래 무채색 아이콘 버튼 한 줄(24~32). 마지막 답변에만 늘 보이고, 앞의 답변은 마우스를 올릴 때 보인다.
  - 메타(모델·토큰·시간)는 동작 줄에 옅은 글자로 둔다. 머리에 배지로 붙이지 않는다.
- **입력창**
  - 모서리 16~28의 상자 하나다. 얇은 무채색 테두리(또는 옅은 회색 바탕)이고 그림자는 없거나 아주 옅다.
  - 안에는 위에 입력, 아래 한 줄에 첨부(왼쪽, 아이콘)와 보내기(오른쪽)를 둔다. 모델 선택을 여기에 둘 수도 있다.
  - 보내기는 화면에서 유일한 채운 버튼이다. 28~36 원이나 둥근 네모이고, 강조색(기본 거의 검정)이다. 입력이 비면 회색 비활성이다.
  - 첨부한 파일·자료는 입력창 안 위쪽에 무채색 칩 한 줄로 둔다. 같은 내용을 머리에 다시 보이지 않는다.
- **빈 상태**: 인사 한 줄(24~32, 굵게) + 입력창. 제안은 없거나 2~5개다. 무채색 윤곽선 칩이나 글자 목록으로 두고, 한 번 쓰면 사라진다. 기능 설명 번호 목록·로고 반복·안내 상자를 쌓지 않는다.
- **오류**: 답변 자리에 빨강 아이콘 + 한 줄 설명 + 글자 버튼(다시 시도)이다. 큰 분홍 상자에 흰 버튼을 넣지 않는다. 키가 없는 것 같은 설정 문제는 입력창 위 한 줄로 한 번만 알린다.
- **코드·도구 블록**: 옅은 회색 바탕(`--color-canvas`) 또는 얇은 테두리 상자 하나, 모서리 8~14. 머리에 언어·복사 버튼을 작은 무채색 글자로 둔다. 도구 실행 내역은 상자 없이 접는 글자 줄로 둔다.
- **좁은 폭(사이드 패널 360~420px)**
  - 머리 한 줄, 대화 열 좌우 16, 입력창 아래 12~16만 남긴다.
  - 맥락(지금 보고 있는 페이지·고른 대상)은 머리 아래 고정 줄이 아니라 입력창의 첨부 칩이나 첫 메시지에 둔다.
- **색**: 무채색 + 강조색 하나(보내기·링크·선택 상태) + 오류 빨강. 공개 구현 두 가지 모두 테마 색이 무채색뿐이고, 유채색은 오류 빨강과 차트뿐이다.
- **하지 말 것**
  - 머리 아래에 페이지·대상·상태 줄을 쌓는다.
  - 같은 대상을 머리와 입력창 두 곳에 보인다.
  - 모델·상태를 주황·초록 알약으로 단다.
  - 보조 버튼(선택·복사·다시 시도)을 회색 채움 알약으로 만든다.
- **관련 패턴**: `file-upload`(첨부), `loading-button`(보내기·중단), `toast-stack`, `dropdown-menu`(모델 선택), `skeleton`(답변 대기).

### 넓은 화면에서 모바일 화면

모바일 기준으로 만든 화면(상세·장바구니·설정·로그인)을 넓은 창에서 열 때의 처리다.

- 페이지 바탕을 옅은 바탕(`--color-canvas`)으로 둔다. 내용은 흰 열 하나(최대 480~560px)로 가운데에 둔다.
- 하단 고정 바도 그 열 폭에 맞춘다.
- 흰 바탕에 좁은 열만 두면 덩그러니 놓인 것처럼 보인다.
- 넓은 화면을 위한 화면이면 열을 늘린다. 예: 장바구니는 상품 목록 | 금액 요약 두 열, 로그인은 가운데 흰 면 하나.

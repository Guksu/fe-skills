# layout-principles — 레이아웃 원칙과 토큰

라이브 데모: https://guksu.github.io/suta/#/layout-principles

## 언제 쓰는가

화면을 새로 짤 때, 또는 만든 화면이 "AI가 만든 것 같다"는 말을 들을 때. AI가 만든 화면은 모든 요소를 같은 무게로 늘어놓는다. 그리고 순서를 정하는 대신 카드·그라데이션·배지로 꾸민다. 이 패턴은 그 반대의 기준이다.

**레이아웃은 꾸미는 일이 아니라 순서를 정하는 일이다.**

1. 무엇을 먼저 보게 할지, 무엇을 같이 묶을지, 무엇을 뺄지 정한다.
2. 그 순서는 값싼 수단으로 보인다. 크기·굵기·색 농도·간격·정렬이다.
3. 비싼 수단은 한두 곳에만 쓴다. 채운 색 면·그림자·그라데이션·상자·장식이다.

반박도 있다. 캠페인 페이지나 브랜드 사이트는 일부러 관례를 깨기도 한다. 그때도 구조는 익숙하게 두고, 힘은 한 요소의 크기나 사진으로 주는 쪽이 안전하다(P11). 이 패턴은 앱·서비스 화면의 기본값이다.

**기술 선택:** CSS 변수(`:root`)와 같은 값의 TS 상수 두 벌이다. 고를 수 있는 값을 줄여 두면 같은 역할이 화면마다 달라지지 않는다. 라이브러리가 아니라서 의존성이 없다. 원칙의 대부분은 사람이 판단한다. 코드만 읽고 잡을 수 있는 것은 `layout-audit` 패턴이 검사한다.

| 파일 | 층 | 복사 대상 |
|------|-----|----------|
| `assets/layout-tokens.css` | 토큰 정본 — 간격 8단계·간격 역할·글자 7단계·굵기 3종·반경 3종·폭·비율 | 모든 프로젝트 |
| `assets/layoutTokens.ts` | 같은 값의 TS 상수 + `toPx`·`isOnGrid`·`nearestSpace`·`groupGapOk` | JS에서 같은 값이 필요할 때 |
| `references/principles.md` | 원칙별 상세(왜·AI 슬롭 증상·코드 기준·검사)와 AI 슬롭 대응표 21행 | 화면을 다듬거나 리뷰할 때 |
| `references/screen-conventions.md` | 화면 유형 11종(홈·목록·격자·상세·검색·결제·폼·설정·빈 상태·시작 안내·시트)의 뼈대·값·하지 말 것·관련 패턴, 넓은 화면(데스크톱 웹) 값 | 화면을 새로 짤 때 |

## 사용 방법

1. **순서부터 정한다(P1).** 그리기 전에 화면에 들어갈 요소를 목록으로 적고 순위를 매긴다. 1순위는 하나다. 넣을 이유를 한 문장으로 말할 수 없는 요소는 뺀다. 화면 유형이 정해져 있으면 `references/screen-conventions.md`에서 그 유형의 뼈대부터 가져온다(P11).
2. `assets/layout-tokens.css`를 복사해 전역 CSS 맨 앞에서 불러온다. 값마다 이유가 적혀 있으니 읽어라.
3. 컴포넌트에서는 숫자 대신 토큰을 쓴다.

```css
@import './layout-tokens.css';

.order {
  display: grid;
  gap: var(--gap-group); /* 묶음 사이 24px */
  padding-inline: var(--page-inline);
  max-inline-size: var(--content-max);
}
.order-row {
  display: grid;
  gap: var(--gap-item); /* 묶음 안 8px — 묶음 사이의 1/3 */
  padding-block: var(--space-4);
  border-bottom: 1px solid var(--line, #e5e7eb); /* 목록 행은 상자 대신 선 한 줄 */
}
.order-label {
  font-size: var(--text-small);
  color: var(--text-secondary, #6b7280); /* 배경 대비 4.5:1 이상 */
}
.order-total {
  font-size: var(--text-display); /* 핵심 수치는 라벨의 2배 이상 */
  font-weight: var(--weight-bold);
  font-variant-numeric: tabular-nums; /* 숫자 폭을 같게 — 위아래로 비교된다 */
  text-align: end;
}
.menu-photo {
  aspect-ratio: var(--ratio-photo);
  object-fit: cover; /* 늘이지 않고 잘라 채운다 */
}
```

```ts
// JS에서 같은 값이 필요할 때 (가상 목록 행 높이, 검사 도구 등)
import { GAP, LIMITS, groupGapOk, isOnGrid, nearestSpace, toPx } from './layoutTokens'

groupGapOk({ inside: GAP.item, between: GAP.group }) // true — 8 ≤ 24 / 2
isOnGrid(toPx('0.6rem') ?? 0) // false — 9.6px는 4px 격자 밖
nearestSpace(13) // 12 — 척도 밖 값을 고칠 때 제안
```

Tailwind 프로젝트는 간격 이름이 같다(`gap-2` = 8px, `gap-6` = 24px). 글자는 `text-xs`(12px) 아래로 내리지 않는다. 반경은 `rounded-lg`·`rounded-xl`·`rounded-3xl` 세 개만 쓴다.

## 원칙 12개

적용하는 순서대로 놓았다. P1~P3은 순서를 정하는 일, P4~P8은 배치, P9~P10은 규격, P11~P12는 검증이다. 원칙마다 왜·AI 슬롭 증상·검사는 `references/principles.md`에 있다.

| # | 원칙 | 코드 기준 |
|---|---|---|
| P1 | **순서부터 정한다** — 1순위는 하나, 이유를 못 대는 요소는 뺀다 | 가장 큰 글자 하나, 채운 주 버튼 하나. 장식은 이유를 주석 한 줄로 쓸 수 있을 때만 |
| P2 | **위계는 크기·굵기·농도로** — 단계 차이가 눈에 띄게 | 핵심 수치는 라벨의 2~3배, 화면 제목은 본문의 1.5배. 굵기 3종. 연한 색 글자는 굵기를 한 단계 올린다 |
| P3 | **강조는 한두 곳에만** — 강한 수단은 화면마다 한두 곳 | 채운 강조색 버튼은 주 행동 하나. 그라데이션·`backdrop-filter`·큰 그림자는 화면에 한두 곳. 그라데이션 글자 금지 |
| P4 | **간격으로 묶는다** — 묶음 안은 묶음 사이의 절반 이하 | `--gap-item` 8 / `--gap-group` 24 / `--gap-section` 48. 간격은 척도에서만 |
| P5 | **상자는 마지막 수단** — 간격 → 선 → 배경 → 테두리 → 그림자 순 | 상자 안에 상자 금지. 목록 행은 `border-bottom` 한 줄이나 `gap`. 카드는 독립 단위에만 한 겹 |
| P6 | **정렬선 하나, 읽는 방향 하나** — 왼쪽 선 하나, 숫자는 오른쪽 한 열 | 기본 `text-align: start`. 가운데 정렬은 짧은 한 줄만. 금액은 `text-align: end` + `tabular-nums` |
| P7 | **줄이지 말고 덜어낸다** — 자리가 모자라면 요소·열을 줄인다 | 글자 12px 이상(모바일 본문 14px), 누르는 영역 44px. 격자는 `repeat(auto-fill, minmax(…, 1fr))` |
| P8 | **빈 곳은 의도로만** — 여백은 묶음을 가르고 초점을 띄울 때만 | 글 덩어리 `max-inline-size: 65ch`, 카드에도 최대 폭. 넓은 화면은 열을 늘린다 |
| P9 | **사진은 가리지 않고 비율을 지킨다** | `aspect-ratio` + `object-fit: cover`. 비율은 사이트에 2~3개. 사진 위 글자에는 스크림 |
| P10 | **규격을 정하고 반복한다** — 반복 단위는 컴포넌트 하나 | 리터럴 대신 토큰. 반경 3종. 같은 역할의 입력칸·버튼은 같은 높이(48px) |
| P11 | **익숙한 구조에서 시작한다** — 개성은 한 요소의 크기로 | 화면 유형의 뼈대(아래 표)에서 시작한다. 탭은 글자 + 밑줄, 하단 탭은 같은 폭 칸, 대등한 선택지는 전체 폭 세로 쌓기, 합계는 영수증 형식 |
| P12 | **실제 데이터와 크기로 확인한다** | 가장 긴 값·빈 값·오류·이미지 없음·320px 폭. flex 자식 `min-inline-size: 0`, 열 폭은 `fr` |

## 화면 유형별 관례

잘 만든 앱 31곳의 실제 화면 1,116장을 유형별로 모아 공통으로 보이는 뼈대를 뽑았다. AI는 어떤 화면이든 같은 틀(히어로 → 카드 3장 → 버튼)로 짜는 경향이 있다. 이 표가 그 반대의 출발점이다. 유형마다 뼈대·값·하지 말 것·관련 패턴은 `references/screen-conventions.md`에 있다.

| 유형 | 뼈대(위→아래) | 핵심 값 |
|---|---|---|
| 모든 화면 | 채운 버튼은 0~1개, 묶음은 간격 → 옅은 띠·선, 왼쪽 정렬선 하나 | 좌우 여백 16~24(흔한 값 20), 주 버튼 높이 44~56 |
| 홈 | 로고·큰 제목 → 배너·바로가기 → [왼쪽 구역 제목 → 가로로 넘기는 줄] 반복 → 하단 탭 | 하단 탭 4~5칸, 다음 카드를 잘라 보인다 |
| 목록 | 상단 바 → 탭·칩·정렬 줄 → 같은 규격 행 반복 | 행은 선이나 간격으로, 금액은 오른쪽 끝 |
| 상세 | 사진(폭 가득) → 이름·가격 → 핵심 정보 → 탭·구역 → **하단 고정 바** | 주 행동이 있으면 하단 고정이 관례, 채운 버튼은 하나 |
| 검색 | 상단 바 = 검색창 → 최근·추천 검색어 → 결과(종류 탭·정렬) | 결과가 없어도 검색창·조건은 남긴다 |
| 폼·로그인 | 질문형 큰 제목 → 라벨 + 입력칸 → 칸 아래 한 줄 안내 → 하단 고정 버튼 | 입력 전 버튼은 같은 자리의 회색 비활성 |
| 설정 | 구역 라벨 → [왼쪽 라벨, 오른쪽 값·스위치·꺾쇠] 행 반복 | 행 높이 50 안팎, 행은 선·간격으로(행마다 카드는 쓰지 않는다) |
| 빈 상태 | 원래 제목·조건은 그대로 → 아이콘 하나 → 한 줄 안내 → 버튼 0~1개 | 버튼은 윤곽선이나 하단 하나 |
| 시작 안내 | 상단 바 없음 → 가운데 큰 제목 + 그림 → 하단 고정 버튼 하나 | 권한 창보다 설명 화면이 먼저 |
| 시트·팝업 | 시트: 손잡이·머리줄 → 내용 / 대화상자: 제목 → 설명 → 같은 폭 버튼 둘 | 뒤 화면을 어둡게, 빨강은 되돌릴 수 없는 행동에만 |

**넓은 화면(데스크톱 웹)**: 잘 만든 웹사이트에서 잰 값이다.

- 본문 16px(긴 글 위주면 18px), 문단 폭은 65ch 이하(중앙값 473px)다.
- 가장 큰 글자는 화면에 한 곳만 48~64px로 둔다(중앙값 50px). 모바일에서는 32~40px이다.
- 콘텐츠 최대 폭은 1120~1280px, 굵기는 2~3종, 반경은 1~2종이다.
- 이 토큰(`--text-hero` 40px)은 모바일 기준이다. 데스크톱 히어로를 키우는 것은 프로젝트가 정한다. 본문·라벨은 키우지 않는다.

## 부딪히는 조언 — 판단 기준

반대로 읽히는 조언도 맥락을 나누면 모순이 아니다.

| 한쪽 | 다른 쪽 | 판단 기준 |
|---|---|---|
| 여백을 과감하게 넓혀라 | 의미 없는 여백은 쓸모없다 | 빈 곳이 묶음을 가르거나 초점을 띄우면 의도된 여백이다. 요소를 늘려 생긴 안쪽 빈 곳은 의미 없다. 빈 곳은 제목과 그 내용 사이가 아니라 묶음 사이에 둔다 |
| 밋밋하게 하라 | 힘을 줘라 | 밋밋함의 원인은 모든 요소가 같은 무게라는 데 있다. 기본은 단순하게, 볼륨은 한두 곳에만 |
| 글자를 줄이지 마라 | 보조 글자는 작고 옅게 | 줄이는 것은 보조 정보뿐이고, 그것도 하한(12px, 대비 4.5:1) 위에서다. 색과 굵기를 둘 다 약하게 하지 않는다 |
| 카드를 걷어 내라 | 카드로 끊어 읽게 하라 | 카드는 한 겹. 독립적으로 열리거나 비교되는 단위, 끊어 읽어야 하는 긴 항목에 쓴다. 이미 묶인 면 안의 행·머리 영역·메뉴에는 쓰지 않는다 |
| 덜어내라 | 필요한 정보는 남겨라 | 기준은 "이 화면의 목적에 쓰이는가"다. 쓰이는 정보는 남기고 같은 폭·간격·순서의 반복으로 정돈한다 |
| 과감하게 키워라 | 평범하고 익숙하게 하라 | 층이 다르다. 구조는 익숙하게, 힘은 한 요소의 크기로 |
| 크기가 다른 카드를 어긋나게 놓아라 | 카드를 흩뿌리지 마라 | 크기로 강약을 줄 때도 바깥 윤곽선과 카드 안 구성은 맞춘다. 사진·개수가 바뀌는 목록은 같은 규격 |
| 같은 줄의 카드는 같은 크기로 | 같은 상자만 반복하지 마라 | 같은 종류의 반복 단위(목록)는 같은 크기. 구역 배치는 큰 것 하나와 작은 것 여럿으로 중요도를 보인다 |

## 커스터마이즈 포인트

| 대상 | 방법 |
|------|------|
| 전체 밀도 | 간격 역할(`--gap-item`·`--gap-group`·`--gap-section`)만 한 단계씩 옮긴다. 묶음 안 ≤ 묶음 사이의 1/2은 유지한다 |
| 글자 크기 | 역할별 값을 바꾸되 하한(`--text-caption` 12px)과 단계 비율(수치 ≥ 라벨×2, 제목 ≥ 본문×1.5)은 지킨다 |
| 반경 | 세 역할의 값만 바꾼다. 네 번째 반경을 만들지 않는다 |
| 브랜드 색·글꼴 | 이 패턴의 범위 밖이다. 프로젝트 디자인 체계를 따르되 강조색은 화면마다 한두 곳(P3) |

## 주의사항

- **토큰을 써도 순서가 없으면 AI 슬롭이다.** 토큰은 값을 맞출 뿐이다. 무엇을 먼저 보이고 무엇을 뺄지는 P1에서 사람이 정한다.
- **상자를 지우면 간격이 그 일을 대신해야 한다.** 카드를 걷어 낸 뒤 묶음 안 간격과 묶음 사이 간격을 다시 나누지 않으면 행이 한 덩어리로 붙어 보인다.
- **`65ch`는 글자 폭 기준이다.** 한글은 한 글자가 숫자 0보다 넓어서 한 줄 35~40자가 된다. 영문 위주 화면은 그대로 65~75자다.
- **보조 글자의 대비는 화면에서 잰다.** 토큰은 크기 하한만 지킨다. 회색 글자가 배경 대비 4.5:1(큰 글자 3:1)을 넘는지는 브라우저 개발자 도구로 확인한다.
- 글자 크기를 화면 폭에 따라 키우는 유동 글자(`clamp()`)는 위계 비율을 흔든다. 쓰려면 제목에만 쓰고 본문·라벨은 고정한다.
